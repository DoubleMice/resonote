46. 办公Agent大战：为什么大厂做不出好AI产品？- 马克汤

嘉宾：马克汤｜AI 应用观察者、财经播客《发财大字》主播

AI 产品 办公效率 产品管理

一则 Workbuddy 的电梯广告，是这场谈话的起点。主持人在周五晚上去按摩的路上，被屏幕提醒可以用 AI 写脚本、做 PPT、画图、写报告；这种不合时宜的勤奋感让人烦躁，却也说明办公 Agent 已经从圈内演示走到大众媒体。机场、地铁和内容创作者的投放一起出现，意味着争夺用户的第一仗，已经由大厂的预算开打。

不过，广告能够换来认知，未必能换来长期使用。对话回顾了 2024 年 Kimi、豆包等 Chatbot 的密集投放：渠道越往后买，获客成本往往越高，而 Chatbot 的变现方式至今没有一个被普遍证明有效。如今推广的重点从通用聊天转到 Work 类、办公类 Agent，问题也随之更具体：大厂既有钱、有人、有数据，为什么仍很少拿出让人一眼觉得非用不可的 AI 产品？

先别把输入框当成 AI 原生

马克汤给出的标准并不复杂：AI 应该处理过去做不到的任务，或把原本无法批量、快速完成的工作推到新的效率等级。投资研究是他用来说明的场景之一。若大量材料可以被快速初筛、整理和比较，工作流本身就有机会改变；这与在原有界面上加一个聊天框不同。

“为了AI而AI”

马克汤用这句话批评把既有 GUI 强行改成语言入口的产品思路。

GUI 已经把常用功能、菜单和操作路径摆在用户面前。若找一个功能、办一件小事都必须先用自然语言描述，交互未必更省力。AI 的价值不在于所有产品都长出一个对话框，而在于它是否真的替用户承担了此前难以承担的判断、整理、执行或协同。节目提到豆包、Gemini、Workbuddy 等产品已积累规模和留存，但也承认，市场还没有看到一个真正重写人们习惯的 AI 时代 Super App。

大厂不是没有资源，而是很难让资源指向同一个用户问题

谈到失败原因，节目没有把答案归结为模型不够强。更常见的障碍是组织。大型公司需要拆目标：算法团队看准确率或多轮对话，产品团队看功能交付，增长团队看活跃和转化，法务团队看风险。每一项任务都合理，但它们之间并不会自然拼成一个好产品。

“每个部门好像都在做自己部门定义下正确的事情”

这句判断指向节目反复讨论的局部理性。

局部理性最棘手的地方在于：它不需要谁故意犯错。任务一旦被层层分解，直接感受用户是否满意的人反而可能最少。更早的项目评审也会放大这个问题。一个刚有雏形的想法，要提前回答市场规模、预期用户、商业化增长与拉新路径；而真正需要探索的，正是这些还没有答案的问题。成熟业务又提供了另一层阻力：新产品若会替代旧产品，旧业务团队并不总有推动它的动力。

节目以语雀、钉钉文档和阿里文档的组织边界为例，说明产品能否合并、谁拥有资源、谁承担损失，往往比点子是否正确更早决定项目速度。这里讨论的是访谈嘉宾的组织观察，不是对相关公司的外部审计。

内部创业能暂时绕开这套机制。节目提到 NotebookLM 的起源：它并非由上而下指定的笔记项目，而是内部少数人从想法开始做出的尝试。但内部创业也要面对期限、绩效、期权和资源归属等现实问题。若没有高层持续授权，团队在有一点成绩后又可能进入赛马、合并和重组。探索需要空间，而空间本身是一种稀缺的组织资源。

独立组织不保证成功，但能改变起跑线

节目把字节的 Flow 当作一种对照。按照访谈中的描述，Flow 与抖音、飞书等原有业务相对拆开，在同一组织里放置模型和产品能力，避免把 AI 直接附着在一个旧产品部门上。嘉宾认为，这种独立性使团队能在一段时间内不被传统业务的短期指标完全牵引。它仍需要可信任的一号位、足够的权限，以及能协调模型、产品和商业化的机制；独立并不是把团队隔离起来就会自动发生创新。

飞书提供的是另一种材料。节目强调它最初服务字节内部的通信和协作，因此把文档、审核、合规等大型组织的实际工作流带进了产品。更值得注意的是模型侧和应用侧之间的关系：飞书或 Lark 调用内部模型时，访谈称双方要结算成本，应用带来的反馈也能回流模型侧。嘉宾将这概括为“亲兄弟明算账”。这类安排的意义，不是制造内部市场的形式感，而是让成本、数据和交付结果都有明确归属。

模型很重要，但用户并不天然忠于模型

海外大厂部分的讨论也说明，基础能力与应用成果不能简单画等号。节目认为 Google 在搜索和 Gemini 上仍保持韧性，NotebookLM 则展示了小团队产品化的可能；Meta 和微软拥有庞大用户与基础设施，却不必然因此占据 AI 应用入口。微软的价值可能更多落在 Azure 和企业接入 AI 的基础设施位置，Office 的文档、表格、演示形态仍在，但具体由哪一个软件承载，并非不可替代。

“模型的忠诚度是零”

嘉宾用 Codex 与 Claude Code 之间的切换解释：用户会直接去用当下更强、更好用的模型。

这一判断的背景是迁移变容易了。若记忆、工具配置和工作资料主要保存在本地，用户换模型或换 Agent 时，不必从零开始。对国内办公 Agent 来说，多模型接入也不全是妥协：即使用户选择了不同的模型，任务编排、工具调用和输入输出仍留在 Agent 所在的平台。平台可以先建立工作流和反馈闭环，日后再决定是否把自有模型变成更强的核心卖点。

真正的入口战争，是谁先理解一整段任务

讨论随后从办公软件走向手机。Apple Intelligence、豆包手机、微信 AI、小程序与各家安卓助手被放进同一个问题里：用户究竟先跟谁说话？如果用户先对手机的 OS Agent 交代任务，系统可以拆分需求，再把不同部分发给应用；如果用户先进入微信、支付宝等 Super App，应用则会在自己的服务网络里继续路由。垂直产品也可能不再争做独立入口，而是作为子 Agent 被上游调用。

开放接口

应用把能力以接口交给 OS 或上游 Agent。任务传递更直接，速度和确定性更好，但需要双方达成协议。

识别界面

Agent 看屏幕、理解页面、模拟点击和滑动。它不必等应用开放接口，却更依赖视觉理解和操作稳定性。

节目用点麻辣烫、叫车去录播客解释上下文的差异。OS 把任务分给外卖和出行服务之后，每个下游服务只掌握局部信息；真正保有整段对话的人，更容易理解一个人的偏好、日程和下一步需要。

“用户其实最终跟谁说话，它能掌握的这个能力是最全的”

这句话概括了 OS、Super App 与垂直服务争夺入口的原因。

这也是为什么应用会担心自己只剩履约角色。访谈设想，如果外卖平台收到的只是地址和商品指令，用户标识、支付和历史偏好都留在上游，它就很难做推荐与排序。嘉宾把这种极端情形比作把平台压缩成厨房。反过来看，OS 也不是必然获胜：硬件层的唤醒路径更短，但关键应用可能不开放接口；超级应用则拥有已有关系和服务网络。谁能提供更好体验、谁能说服更多服务开放能力，仍是待解的竞争。

供给变多以后，分发和评估都要重做

Cursor、Claude Code 等编程 Agent 降低了把想法做成应用的门槛。节目据此推测，当应用供给增加，渠道会重新成为稀缺资源：未来的预装不只为了让用户看到应用，也可能为了让某类意图优先路由到某个服务。嘉宾把它类比为移动互联网早期的预装竞争；这是一项预测，而非已经发生的事实。

产品内部的考核同样会变。日活、月活和商业化仍是结果指标，但它们无法解释问题出在哪里。访谈提到的过程信号包括平均对话轮次、用户在多轮对话中是否反复纠错、是否出现负面情绪，以及用户隔天或当天会不会继续回来。对办公工具而言，用户也不必长时间停留：若它完成了一项高价值任务，付费和营收可能比屏幕时长更重要。

先看过程

回答是否要反复修改？用户是否把同一类任务交给它？这些信号帮助团队定位问题。

再看结果

留存、付费和营收回答产品有没有形成真实价值，而不是只积累一次性注册。

价值可以集中

办公 Agent 不必覆盖所有人；少量高价值用户也可能支撑一门业务。

办公场景先行，代价也会先显现

对未来 12 个月，马克汤没有给出谁会赢的名单。他更倾向于认为竞争先集中在办公场景：程序员、白领、法律、金融等知识工作有较高的经济价值，且大量流程已经数字化，因而更容易衡量 Agent 是否节省时间、减少人力或带来营收。模型能力跨过足够能用的门槛后，产品可能从辅助工作向替代部分流程移动；这仍是访谈中的预测，不应被读作既成结果。

这也改变了公司内部使用 AI 的方式。节目把一段鼓励所有人尽量多用 token 的阶段称作探索期：公司先给工具和资源，之后则看谁确实放大了产出。嘉宾说：现在这个比赛结束了。这里的比赛指只比 token 消耗的阶段，而不是停止使用 AI。后续真正被看见的，是任务完成质量、工作效率和业务结果。

对于人力变化，节目提出了一个需要谨慎观察的信号：自然流动之后，公司补人的比例是否下降。不同公司岗位结构不同，员工总数也不能直接证明哪些工作被替代；但随着知识资产沉淀在电脑和数字系统中，组织会更容易把重复流程交给模型、检索系统和 Agent。管理者之所以更快理解这笔账，不是因为他们更懂技术，而是因为他们直接承担工资、产出和风险之间的取舍。
