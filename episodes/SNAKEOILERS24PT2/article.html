Snake Oilers：智能体沙箱、API 权限与威胁情报查询

嘉宾：Jake King、Alex Ferguson、Simon Warren｜来源：Risky Business｜2026 年 10 月

在这期 Risky Business 的厂商推介节目中，主持人 Patrick Gray 分别采访了 Minimal.dev、RequestRocket 和 TRM Labs 的代表。三家公司讨论的产品各不相同：一个为 AI 智能体提供隔离运行环境，一个在调用第三方 API 时增加权限控制，另一个让分析师按使用量查询多家威胁情报供应商的数据。节目中的产品能力和效果主要来自厂商介绍，并非独立测试结果。

Minimal.dev：让智能体只拿到必要的权限

Minimal.dev 的 Jake King 此前联合创办了 Linux 安全公司 CMD，后来该公司被 Elastic 收购。他的新项目最初聚焦编程智能体：开发者可以让智能体在隔离环境中运行，同时限制它接触的网络、进程、资源和凭据。King 认为，企业需要让智能体访问内部代码库和工具，但授权范围应限于任务所需，不能因为任务本身范围较小就默认开放互联网。

除了网络出入站控制，King 还提到要弄清智能体从哪里获取资源、运行时做了什么，以及如何收集运行记录。他希望这些环境可以迁移，避免用户被单一供应商绑定。Gray 则提醒，节目中提到的一些智能体异常行为可能属于安全或漏洞利用任务中的边缘情况，与让智能体更新企业网页应用不同；不过，他也认同大型模型厂商正在争取企业客户。

两人讨论了开放权重模型与开源智能体的组合。Gray 设想，企业可以为开源智能体添加所需功能，再按任务选择模型；King 认为，针对具体用途定制系统提示词、工具和模型，比一直使用通用智能体更符合部分企业需求。他也说，自己运行模型推理的部分原因是某些任务成本较低，而模型能力已经足够完成日常工作。选择哪种组合，仍取决于任务和企业希望自行管理多少部分。

King 介绍，Minimal 使用 libkrun 提供隔离，在 Linux 和 macOS 上限制网络、进程和资源访问。开发者在本机启动多个智能体时，每个智能体可以分别获得所需的环境；随着使用规模扩大，也可以转到企业自己的云计算资源，或使用厂商可能提供的托管环境。

在环境的软件供应链方面，King 说团队直接从上游获取 Go、Rust 等运行时依赖并构建环境组件，目标是达到 SLSA 四级；他估计项目在早期阶段大约处于三级。Windows 支持当时仍在推进；他提到 Windows Subsystem for Linux，但没有确认已经形成可直接使用的方案。

RequestRocket：给第三方 API 加一层权限

RequestRocket 创始人 Alex Ferguson 长期从事系统集成。他说，不同应用的认证方式和实现细节不一致，连接之前往往就需要解决认证问题。RequestRocket 使用代理转换认证方式；例如，面对商业智能工具与第三方系统支持的认证方式不匹配，代理可以帮助两者对接。

Ferguson 还讲了一个促使他重视授权范围的经历：大约五年前，他为一家全球薪资服务商的某个客户开发集成，对方给他的密钥却能访问当时约 50 家公司的薪资和员工个人资料。他只需要其中一家公司的数据，却无法由客户自行缩小这把密钥的权限。

按照他的介绍，RequestRocket 在原有系统前增加可配置的授权层，根据调用者身份和规则决定是否允许某个 API 请求。它也可以过滤返回的数据：例如医生查询患者列表时，只返回属于该医生的患者，并移除不需要的医疗保险或银行资料。Gray 将这种做法类比为数据库里的行级、列级访问控制，只是控制位置移到了 API 层。

这对无法修改的第三方系统尤其有意义：代理可以限制经过它的请求和响应，即使原系统只提供权限宽泛的密钥。Ferguson 认为，这种需求并不限于旧系统，一些新应用也可能只提供范围很宽的 API 密钥。Gray 预计业界会逐渐改进权限范围，但这个过程可能很漫长；Ferguson 补充说，有些系统本身无法使用 OAuth 的权限范围。

请求经过代理还可以留下审计和故障排查记录。Ferguson 说，集成出错后，开发者常常要翻查日志，问题却可能出在令牌过期或上游服务不可用。他举例称，一位客户查看记录后，几分钟内就发现其客户撤销了凭据，导致集成无法访问目标系统。Gray 认为，出了问题后能查清谁在何时访问了什么，比单纯追求复杂的异常检测更贴近一些用户的需要。

TRM Labs：按使用量查询多源威胁情报

TRM Labs 的 Simon Warren 介绍了威胁情报调查平台 Ardent。TRM Labs 最初从事区块链分析，如今也处理更广泛的情报。Warren 说，平台整合了 50 多家数据合作方、超过 100 个接口；客户用自然语言提出问题后，系统的分析层和 AI 选择要调用的接口，有时会并行调用数十个接口。

Warren 将它与威胁情报平台常见的订阅方式作比较：后者的客户通常选择要接入的情报源，并为各个数据源另付订阅费。按照他的描述，Ardent 的合作数据源已经纳入平台，用户按使用量付费，因此可以在需要时查询原本未必会单独订阅的数据，例如制裁名单或区块链情报。Gray 认为，这也可能让分析师发现值得进一步单独订阅的数据源。厂商认为这种计费组合比较新，节目没有独立验证其市场独特性。

费用控制是这种模式的实际问题。Warren 说，有些查询很便宜，另一些数据调用可能很贵；如果让系统对发现的 3000 个邮箱地址逐一调用所有数据源，可能产生数十万次 API 调用。团队会在客户接入时按需求启用相关数据源、关闭无关来源，也可以设置额度上限：硬上限到达后停止使用，软上限则在达到分配额度时提醒用户。

他用勒索软件调查说明多源查询的用途：分析师先询问某个行业近期受到的影响，再围绕结果追查某个组织的战术、技术和程序，查找相关钱包交易，或查询公司凭据是否泄露。分析师可以要求系统汇总结果，生成面向首席信息安全官的简报。Warren 表示，系统会让分析师参与调查，而不是自行完成所有步骤。

Gray 问到能否将威胁信息与客户自己的资产匹配，以判断哪些设备存在风险。Warren 回答说，这项能力当时尚未具备，团队正在朝那个方向开发。他也希望产品接入现有安全信息与事件管理、自动化响应等工作流，并设想未来通过 MCP 在 Splunk 等工具中触发查询；这同样是开发方向，而非节目中确认已经提供的功能。

在常规网络威胁数据之外，Warren 举例说，调查人员可以查询人物或公司是否出现在制裁名单上，再寻找关联公司或人员的信息。对勒索软件调查，区块链数据还可以帮助分析已知钱包的交易及关联交易所；他说，平台会向用户建议是否继续调查钱包交易、追踪多少跳以及寻找可能的资金兑出点。
