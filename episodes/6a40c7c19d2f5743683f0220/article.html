40. AI应用能融下一轮吗？收购、擦边、中转站、大厂围猎

嘉宾：马克汤，AI 应用创业者、播客《发财搭子》主播

讨论对象
模型能力提高后，AI 应用如何证明自己不是短暂的接口层。
判断尺度
数据、交付、留存、推理成本和毛利要放在一起看。
延伸问题
AI 的机会也可能藏在持牌、线下和流程复杂的传统企业里。

应用的窗口，是模型跨过可用阈值之后才打开的

这期对话从一个时间差开始。马克汤回忆，2023 年初可用的最好模型还是 GPT-3.5，国内模型也处在较早阶段。模型能聊天，并不等于它能可靠地完成一段工作流程。到 GPT-4o 出现后，他感到一些原本无法落地的任务开始可以执行，AI 应用才有了更大的试验空间。

一批产品在 2023 年中后陆续出现，并在 2024、2025 年伴随模型迭代加速。早期的想象很像移动互联网：新的入口会不会带来新的淘宝、小红书或抖音？主持人 Raymond 把问题收得更具体：这些应用公司能否拿到下一轮融资？

马克汤的回答没有把融资当作唯一信号。传统互联网常用 DAU 衡量机会，因为流量后面可以接广告、电商或信息流。AI 应用的账更直接：它是否赚钱，用户是否愿意留下，以及通用模型产品能否很快覆盖同一件事。投资人也得同时理解模型能力、应用流程和两者之间不断变化的边界。

企业端仍有空位，因为真实交付不只有模型

对话先把市场分为面向个人和面向企业。企业产品又分成标准化 SaaS 与项目制：前者能把相似的需求复制给多家公司，后者需要进入一家企业的流程、数据和权限结构。马克汤认为，中国企业端更常见本地部署，法律、金融、医疗、汽车等高价值领域尤其如此。客户要保护数据，也需要现有算力承载服务。

模型公司当然会去做这些领域。节目提到 OpenAI 招募量化背景人才，Anthropic 请华尔街分析师标注 DCF 估值模型中的关键假设。法律、医疗和金融直接关系到诉讼结果、财富或生命安全，价值足够高，模型平台不会忽略。

不过，进入企业并不只是发布一个技能或插件。过去做 To B 项目时，团队要在客户现场工作，理解合规、审计、固定 SOP 和项目管理。模型公司有技术与资金，却未必愿意立刻把自己变成驻场服务公司。对垂类厂商而言，这段交付过程仍是存在的理由；对客户而言，稳定地把系统接进既有流程，比一次出色的演示更重要。

企业端的应用价值常由两部分构成：模型输出的能力，以及把输出放进权限、流程、审计和责任边界后的可用性。后者需要长期理解客户，难以只靠一次模型更新补齐。

数据壁垒不等于多存一批文本

讨论 Harvey 时，两位主播把数据壁垒拆开了。法律文本看起来都是文字，通用模型也能处理文字；如果资料公开、非排他，而且 ChatGPT 或 Claude 可以取到，先做应用的人很难长期独占。马克汤认为，真正有价值的是公域里拿不到的资料，例如机构可见的研究报告、会议纪要，或具有私有性的业务数据。

即使拿到资料，下一步也不是直接丢给模型。在财搭子 AI 的投资场景中，数据管线要区分客观事实和主观观点。股价、财务数字属于事实；研究判断和市场看法则需要在下游推理中做交叉验证、观察分布。事件的重要程度、分类方式和召回结果，也都会影响最终回答。

这类工作通常被叫作 dirty work：清洗、聚类、归类、打标、准备检索结构。它不显眼，却决定同样搜索十条结果时，产品能否给出更相关、更准确的内容。对于需要马上交付的任务，预处理还有一个实际好处：过去已经完成的整理不必在每次请求中重新消耗 token。

容易复制的资料

公开、非排他的文档。模型厂商和其他应用都可能购买、索引或重新整理。

更难复制的能力

稳定的数据供给、贴合任务的清洗规则、检索质量，以及把资料用于特定推理流程的经验。

效率要看任务的时间窗口

马克汤没有把速度说成放之四海皆准的优势。十分钟后就要开会、演示文稿还没完成时，速度本身就是产品价值；如果智能体在用户睡觉时运行四五小时，缩短一两个小时未必改变即时体验。不过，较短的推理路径仍会影响成本，所以效率同样影响商业模式。

他以编码工具说明这种取舍。节目将 Claude Code 的目录浏览方式描述为逐层寻找上下文；Cursor 则大量使用类似文件搜索的方式，直接定位可能相关的片段。后者能节省 token、加快响应，也可能减少推理时看到的信息。工程优化因此不是装饰，它会落在准确度、速度和每次任务的成本上。

这也是应用公司面对上游模型的复杂处境。调用闭源 API 的产品会把大量高价值请求交给模型厂商。节目认为，平台能从这些请求中发现共性，改进后续模型和产品。应用既依赖供应商，又可能为供应商提供了理解真实需求的窗口。

编码工具的竞争，发生在入口、成本与习惯之间

对话多次回到 Cursor、Claude Code 与 Codex。主持人把 Cursor 的近况当作一个尖锐问题：当上游自己推出更强的编码产品，接口层的工程优势能支撑多久？马克汤认为，Cursor 的工程化确有价值，也需要控制推理成本；如果应用以高价购买上游模型，给用户同等额度时就很难保住自己的毛利。

但用户不会只按模型排行榜切换。有些开发者已经习惯 VS Code 式界面，也愿意继续检查每一段代码的修改；另一些用户更喜欢直接描述需求，验收最后交付物。熟悉的操作界面、过去获得的好结果和团队协作方式，都构成迁移成本。

编码还有一层特殊性：用户愿意为高价值任务付费，模型公司也把它当作训练能力的重要数据来源。因此，编码入口特别拥挤。Chat、Work、Code 等产品分层背后也有成本考虑：简单问答不需要本地文件、技能和长上下文；更复杂的任务会用到更多上下文，也更可能把需求变成可交付结果。

个人产品的两条路：提高效率，或者占住关系

面向个人的 AI 产品目前仍以效率工具为主。演示文稿就是一个有趣例子：AIPPT、Gamma 等产品把模板、素材和制作流程做成了清晰的场景，市场需求依然存在。马克汤所在团队却把内部研究总结和现场展示更多做成 HTML 页面，因为页面可以支持动态交互，不必受限于幻灯片的逐页展示。

陪伴产品走的是另一条路。角色设定、文字风格、行动描述和抽卡机制能让对话接近游戏；长期记忆和主动提醒则可能让用户产生更强的关系感。与此同时，节目也谈到内容尺度和未成年受众的问题。部分产品走向擦边内容，与其说是产品形式的必然，不如说是年轻受众支付能力有限、商业化压力很大的结果。

图像和视频生成产品也面对类似的用户分层。成熟创作者能接受等待二三十秒得到一张图，普通用户却可能在第一次反馈来得太慢时直接离开。节目给出的方向是收窄客群：模型速度还有限时，服务愿意等待、也有明确付费理由的创作者，再考虑扩展到更广的人群。

视频 wrapper 与中转站，显示了上游依赖的两面

嘉宾以 Liblib、Lovart 和 LibTV 一类创作产品为例，说明视频应用不只调用基础模型，也会增加脚本、分镜和创作流程，让用户更容易完成作品。底层模型能力显著提升时，这些产品可以迅速获得用户；它们的风险也同样明显：模型成本高，平台能看到调用集中在哪里，并有机会把有效功能收进自己的产品。

节目还谈到国内常见的中转站现象。两位主播把它解释为账号额度、企业优惠券和其他可调用配额形成的供给池，应用因而可能以低于标准渠道的价格取得 token。这种渠道让应用的进货成本受到供给池影响；能否长期经营，仍要回到定价与用户价值。

字节的筹码，是多模态与既有工作资料

在中国大厂的讨论里，马克汤对字节的评价很高。他认为 Seed 系列模型没有掉队，在语音、图像和视频等多模态任务上尤其有优势；豆包、即梦、猫箱与剪映又提供了面向用户的入口。模型能力到达可用水平后，已有分发和产品经验可以让应用层迭代得更快。

飞书是访谈中更具体的案例。它在 AI 之前就有文档、评论、机器人、多维表格和比较完整的接口说明。现在，智能体可以读取文档和评论，按照固定流程检查产品文档；也能把研究结果写回文档或表格，定时检查接口是否异常。资料并没有只停在聊天记录里，而是可以被团队继续查看和使用。

权限边界决定这件事能否在组织里扩展。马克汤提到，他把自己的智能体分成可读写与只读两类：前者处理个人电脑上的文件，后者供同事查询指定范围的资料。飞书的价值因而不仅是多了一个聊天机器人，它把工作资料、协作关系和可控权限放进了智能体能够调用的环境。

高 ARR 之外，必须把毛利算清楚

主持人反复追问一个容易被融资新闻掩盖的问题：应用到底赚不赚钱。马克汤的回答是，AI 应用不能照搬传统软件的毛利预期。传统软件常有很高毛利，应用公司却要把模型公司的 API 价格当作自己的成本。模型端可以有较高毛利，应用端却还要支付获客、服务与基础设施费用。

因此，高 ARR 不能单独说明产品健康。一家向消费者售卖图像、视频或复杂智能体服务的公司，可能收入增长很快，推理成本却也很高。面向明确专业人群的产品更有机会收取溢价；再配合更有效率的数据管线和任务设计，才可能留下可用的毛利。节目中，马克汤把能做到 50% 至 60% 以上毛利视作很好的水平，这是一位应用创业者对成本结构的判断。

评估一款 AI 应用时，至少要同时看五件事：它是否有稳定数据来源，是否能提高任务效率，用户为什么不换，模型成本后还剩多少毛利，以及上游复制能力后它还留下什么优势。

AI 改造也可以从一家老公司开始

这场对话没有把 AI 应用局限在新 App。节目提到 AI roll-up 的思路：收购或改造一家已有商业模式的传统企业，再把模型用于获客、客服、客户预筛和长尾服务。保险公司有牌照、客户关系与 SOP，线下零售、医院和制造业也有模型难以直接穿透的现实结构。

这类公司并不缺一个漂亮的聊天框。它们更需要把固定规则、人工触达和复杂服务环节重新组织起来。AI 可以扩大服务半径，处理过去因人力成本太高而被忽略的需求；现有企业则带来牌照、客户和可验证的收入模型。主持人把它比作并购后运营改造，马克汤把它视作模型进入真实世界业务的一条路径。

产品层的 AI 化还不够。马克汤把组织层也放进判断：迭代速度、内部沟通成本、知识库的上下文透明度与层级关系，都会影响一家公司能否持续用好模型。旧公司可以增加 AI 功能，能否形成相应的组织能力则是另一回事。

应用负责把基础设施变成用户愿意买单的结果

节目最后回到投资选择。马克汤会选择 AI 应用，因为人们会为改善体验、提高效率的产品付款。模型、芯片、算力中心和电力提供能力供给；应用的职责是把这些供给交付给具体的人和工作。

因此，AI 应用能否融到下一轮，不会由一条融资新闻决定。更值得观察的是，它是否在模型能力快速上升时仍有具体的交付位置，是否把成本留在可承受范围内，是否能在用户、企业流程或现实世界业务中积累难以替代的关系。应用被使用、被持续付费，才会让整条技术投入形成可验证的商业循环。
