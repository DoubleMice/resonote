E256｜Agent、机器人与制药，谁先被GPT-6 Astra改写？

嘉宾：许华哲（破壳机器人创始人、清华交叉信息研究院助理教授）；朱哲清 Bill（Pocket AI 创始人兼 CEO）；王胜（华盛顿大学计算机学院助理教授）

来源：硅谷101 · 发布：2026 年 10 月

Agent机器人AI 科研技术访谈

Astra 发布三周后，三位嘉宾讨论的已经不只是模型分数，而是它进入不同产业后会卡在哪里。个人 Agent 需要进入网站和完成交易，机器人需要在物理环境中及时反应，制药则必须等到真实实验给出反馈。同一套长程推理、视觉理解和电脑操作能力，在这三条路径上遇到的阻力并不相同。

Agent浏览网页并不等于能持续获得网站许可；身份、访问权和推理成本决定服务能否经营。
机器人模型能把三维理解带到更低层动作，但速度、直觉物理和本地控制仍是部署条件。
制药干实验可以很快提出候选方案；湿实验的周期、设备和数据决定下一轮验证能否开展。

模型能力先显现在长程任务里

许华哲从机器人测试中看到，Astra 能根据碰撞、空间大小和前一次结果调整下一步动作。他举例说，把一枝底部劈开的花插进花瓶时，模型会先把分叉处捏窄，再尝试放入。在他看来，这显示模型能把三维尺寸判断接到相对静态的操作上；它离完整的物理常识还有距离。

它还让从真实环境生成仿真的工作更省力。过去要拍摄大量照片和视频，并手工标定、修改环境；现在用少量图像就能较快复现办公室或实验室的外观，供机器人在仿真中训练。许华哲同时提醒，外观更像真实环境，不会让物理引擎自动变得准确。把 real-to-sim 的进步直接当作 sim-to-real 已经解决，容易高估它对机器人策略的帮助。

朱哲清的体感更克制。就编程而言，他认为此前一轮模型已让工具调用和较长任务发生明显变化；Astra 的提升主要是把可完成的任务拉得更长，并让上下文与已完成步骤更稳定。让模型连续运行一夜时，幻觉仍会出现，响应也较慢。对他来说，这不是一个突然能解决全新编程问题的分界点。

王胜则在生物医学软件上看到了更直接的用途。许多领域内长期沿用的工具界面陈旧、术语密集，跨学科研究者很难上手。Astra 的 computer use 可以看屏幕、移动鼠标、输入文字，按一连串界面操作完成任务；王胜提到 MultiQC 这类常用工具，也说研究者可以从模型的操作过程里学习软件用法。对于会持续八到二十四小时的生物医学流程，他更愿意在夜间把长程 pipeline 交给较慢的模型执行。

这种能力不改变软件系统的权限设置。computer use 只是让模型像用户一样使用视觉界面和输入输出设备，它没有天然获得 API、账号或数据权限。一旦模型触及这些现实接口，便会面对不同的行业约束。

个人 Agent 的难题是访问权和单位成本

购物、旅行和客服等场景往往没有可供 Agent 调用的开放接口，浏览器操作因而又变得重要。朱哲清认为，许多应用一度期待所有服务都提供 API 或面向 Agent 的入口；现实中，第三方应用和购物、旅行网站并不总愿意开放。节目把 MetaMuse 和 Manas 作为例子，讨论云端虚拟机执行 browser use 时如何受到网站屏蔽。

主持人与嘉宾把这件事归到身份识别上。商家可以接受一个用户委托一个 Agent 访问，却未必愿意让无法识别身份的云端机器同时派出大量 Agent 比价、抓取页面或改变流量入口。若任务在用户自己的电脑、手机或其他硬件上执行，网站较容易把网络行为与真实用户关联；这只是他们提出的可能路径，仍要解决终端安全、平台规则和软硬件合作的问题。

云端浏览器
便于集中运行，却可能因商用 IP、身份不清和网站反爬规则失去访问权。
本地或私有算力
更接近用户自身的设备与网络；能否获准访问，仍取决于平台和安全机制。

成本是另一条约束。主持人按输入 token 粗略估算，节目所谈服务每名用户每周的一亿免费 token 约相当于一百美元成本；这只是他的估计，不是产品公开财报。除了推理，云端虚拟机的 CPU、内存和 sandbox 也会消耗预算。朱哲清的团队因此把约 30B 的模型部署到端侧或私有算力当作一个方向：能在本地完成的任务不必全部路由给前沿大模型。即便如此，难任务仍可能需要更强模型，面向消费者的免费额度能否长期维持，取决于模型成本继续下降和产品是否找到合适的分工。

企业采用也不是由功能一项决定。朱哲清观察到，在法律、医疗等传统企业里，有些员工还受制于既有办公软件和权限，未必能自由使用新的编码或工作流产品。Astra 可以协调更多步骤，不代表组织已经准备好交出数据、访问权和责任边界。

机器人需要把慢推理接到快反应上

机器人领域的惊喜来自 Astra 能把任务规划往下延伸。以往视觉语言模型可能会把做番茄炒蛋拆成开冰箱、取食材等步骤，低层模型再负责怎么开门、怎么拿鸡蛋。许华哲观察到，Astra 已能给出手向右移动两厘米、没有抓住就再向前靠近一类更细的指令。层级边界因此要重新讨论，而不是简单沿用过去的规划层和控制层划分。

它还不能替代快速控制。许华哲说，网上许多 Astra 控制演示需要以十六倍或二十四倍速观看；模型在简单任务和复杂任务上花的思考时间也相近。抓取小球时，他自己的模型会连续尝试，并依据每次接触后的状态调整；Astra 则会在每一步后分析原因，分析错了可能停在原地。旋转物体、插入小孔、双臂折衣服等需要灵巧协调的任务，仍暴露出它对即时物理反馈和直觉物理的不足。

较大的慢模型
适合长程规划、三维理解和较静态的操作；能给低层控制更多信息，但推理延迟高。
本地快速模型
适合连续反馈和高动态动作；要在极短时间内处理接触、平衡与突发变化。

在许华哲看来，落地机器人的本地模型以小于 10B 的规模较为舒适，十几 B 或几十 B 也能运行，但会提高芯片和硬件成本。云端模型的规模限制较少；对于准静态任务，他认为约二百毫秒乃至数百毫秒的网络延迟可以接受。倒水等时间敏感的动作则必须依靠本地控制，因为一次卡顿就可能破坏任务。这些数字是他按任务类型给出的工程判断，并非所有机器人都适用的统一标准。

这也改变了不同公司的选择。质量足够好的机器人本体可以较快接入通用模型做出展示级能力；做机器人模型的团队，则可能训练更小、更快的模型，或把自己的模块做成可被大模型调用的工具。许华哲特别强调数据标注的变化：除了记录做了什么，还要标清为何成功或失败，例如没有抓住物体是位置偏了还是表面太滑。原始数据可以规模化采集，能把因果和直觉物理标清的高质量数据则需要更理解前沿模型训练方式的人来制作。

AI 制药要等到湿实验返回结果

谈到 AI for Science，嘉宾反复指出现有基准不足以代表药物发现。王胜认为，编程、文献检索和长程任务的提升，已经让模型在许多干实验工作中很有帮助；朱哲清则补充，进展更多来自这些通用能力，而非生物医学知识基准本身的显著跃升。模型对某些生物医学问题的安全拒答，也会让实际使用比跑分更困难。

干实验在计算机里完成预测、分析和模拟；湿实验则要在实验室中使用细胞、培养皿和动物验证。药物问题的答案原本未知，预测一个候选分子并不能说明它有效。研究者还需要知道如何合成、储存和给药，怎样安排实验周期，并让方案匹配实验室已经拥有的设备和材料。王胜估计，现有模型在实验设计中的完成度约为三成，剩下的修改往往需要熟悉具体实验的技术人员，而不只是宽泛领域知识。

这解释了模型更新为何快过制药迭代。节目中给出的典型流程是：细胞和小鼠实验可能花数周；灵长类动物实验单次就需约四个月，若做两次则可能延长到八个月。一家 AI 制药公司做到猴子实验后，可能把后续人体实验授权给大型药厂；嘉宾据此把做到该阶段的周期放在六到十二个月。模型可以在这期间换代，动物的新陈代谢和人体试验却不会按算力速度缩短。

实验室是反馈系统的一部分
模型提出候选分子后，湿实验要给出可用结果；这些结果再成为下一轮模型和实验设计的依据。缩短交接和等待，比单独加快生成一个分子更接近制药流程的瓶颈。

因此，王胜认为想认真用 AI 做药物发现的团队需要自己的实验室，也要围绕模型改造实验流程：把细胞、材料和前置条件准备好，让模型在需要作出选择的环节接入，而不是把一个抽象方案交给不了解其上下文的合作方重新设计实验。他把这种目标延伸为 human use：模型不只操作电脑，还要产生清晰、可执行的指令，协调实验员、机器人、预算和设备等真实世界资源。

数据的价值也随之改变。来自完整动物实验的结果不在互联网预训练语料中，成本高、周期长，却能回答候选分子在现实中是否有效。王胜提议把评估题目设计成没有固定上限的改进任务，例如在持续湿实验反馈下，让模型努力把药物杀死癌细胞的比例从既有水平继续提高，而不是反复完成一个已有标准答案的分类题。这个设想的前提正是持续投入实验资源；它不是只靠更大模型就能完成的基准替换。

能力曲线之外，是各行业自己的验证周期

节目没有把人放在模型能力的对立面。讨论蒸馏时，许华哲认为今天机器人的大量日常技能仍值得记录；王胜则把更难的目标放在模型能否从交互中学习一个新领域，而非只记住训练中见过的知识。对于医学，研究者仍要选择值得投入的问题，并参与会影响病人和大量资源的决策。

朱哲清预计，通用机器人在 2028 年初会开始进入真正实用的阶段，并认为约十八个月后可能出现能以语言完成多数家庭任务的产品。这是他在节目中的预测，许华哲当场称其激进。两人的分歧恰好说明，模型演示与稳定部署之间还隔着速度、硬件、泛化和场景容错。

主持人最后把三条线索放在一起：AI 圈看到的是能力曲线，行业参与者面对的却是验证和落地周期。Agent 要得到商家和用户的许可，机器人要在真实环境中反复试错，制药要等待动物和人体的反应。Astra 的出现让这些环节更值得重新设计，但它们不会因为一次模型发布而同时消失。
