Claude Code 之后，Agent 怎样从货架走向工作现场

嘉宾：陈宇森，MuleRun 创始人兼 CEO

这期访谈分两次录制。第一次在 2025 年 12 月，陈宇森谈的是 Agent Marketplace 如何启动；不到一个月后，MuleRun 的 Agent Builder 开始内测，团队已经在重新思考创作工具、产品入口和交易系统。谈话的后半段则回到他十余年的创业经历：长亭科技的上升期、两家公司并行创业时的失误，以及从低谷中恢复之后重新开始做 AI。

为什么不继续做一个 Vibe Coding 产品

团队最早从 Cursor 找到产品市场匹配得到启发。模型的编程能力增强之后，编程不再只是程序员的工具；它可能成为模型接触更多数字工作的桥梁。MuleRun 曾经做过接近 Lovable 的 Vibe Coding 产品，但内测后的感受很直接：把相同提示词交给不同产品，做出的网页和大多数任务结果没有拉开明显差距。模型 API 的能力很大程度决定了上限，后来者很难仅靠界面或细节赢得用户。

陈宇森因此把问题往前推了一步。假如一个足够强的编程智能体已经能理解任务、写出执行代码，那么新的稀缺资源是什么？他把注意力转向个人脑中和线下的工作知识，尝试把它们做成可运行、可复用的智能体。招聘、客服、销售和供应链人员每天都知道自己要查什么、在哪个软件里操作、遇到例外怎样判断；这些经验过去很难被完整写成规则。模型能处理其中一部分判断，才让流程从半自动化走向真正可交付的自动化。

“其实现在最强的general agents是Claude Code。”

陈宇森，谈团队转向的前提

这句话在访谈里是产品路线的前提，不是模型排行榜结论。陈宇森所说的 Claude Code，也包括它所代表的一类 Base Agent：它已经具备任务循环和上下文管理，不必让每家创业公司从底层重做一遍。创业团队可以在上面补齐环境、工具、编辑体验和分发方式，让原本不打开终端的人也能把工作做成一个智能体。

长尾需求终于值得被做成软件

软件开发的传统经济性决定了产品要寻找大共性。做一个应用需要设计、开发、部署和维护，用户太少就难以支撑成本。陈宇森用 3D 打印作比喻：工业生产擅长制造大量相同物品，而 3D 打印可以为几个人做一件真正需要的东西。Vibe Coding 和 Agent Builder 若把创作成本继续压低，十个人、五个人，甚至一个人的工作需求也有机会被认真对待。

以前

应用通常要服务上千或上万人的共同需求，团队才有理由投入开发和维护。

现在

一个人可以描述自己的工作过程，借助已有的 Agent 能力拼出一个只服务小群体的工具。

平台的机会

把创作者的经验和部署条件保存下来，让遇到相同问题的人不必从头学习整套操作。

访谈里最具体的例子来自 Nano Banana 热潮。对熟悉 AI 工具的人而言，找到 Gemini 或 Google AI Studio、搜索提示词、上传图片并拿回结果不算难；对更多用户而言，这些步骤已经足以形成门槛。平台上的创作者把它封装成一个小工作流：用户上传图片，流程调用提示词和图像服务，再把结果返回。单价不高，但在需求高峰期也能有可观使用量。能力到达用户之前，仍需要有人把访问、选择和流程整理好。

这也解释了陈宇森对日抛式软件的想象。他没有说长期软件会立刻消失。近处的目标是先做出少数人每天都愿意使用的工具；更远的情形是，代码为一个明确目的被生成、运行，任务结束后就不再保留。那时软件更像按需制造。它并非没有成本：每次生成和运行仍要消耗 Token 与算力，成本高低还受模型能力差异和供需影响。

Skills 让模型少读一些，也少猜一些

复杂任务不能把所有说明、资料和步骤塞进同一段提示词。陈宇森把 Skills 放在 Context Engineering 的框架里解释：智能体先看到技能的简介，知道每个技能解决什么问题；遇到相关任务时，再读取相应的详细文档、程序或接口。浏览器操作、表格处理、调用外部 API 等知识，不必在每次任务开始时全部装进上下文。

Skill 还有提示词模板之外的形式。有些 Skill 附带写好的程序；有些告诉智能体在特定问题上该调用一个 API，直接取得结果。这里的分工很朴素：模型适合做分类不完整、需要理解上下文的判断；确定的数值比较、转换和提取，交给代码更可靠。MuleRun 的生产场景用 SOP 承担可确定的步骤，让模型负责中间难以规则化的部分。

从 Skill 目录到 Skill 市场，增加的是责任。 同一个任务可能有多个候选 Skill，平台需要评测它们在相同任务中的表现；如果 Skill 运行在用户电脑上，还要检查它是否会借助 Shell 等机制取得不该有的权限。

这套工作与 Marketplace 的早期设想紧密相连。平台不能只负责让创作者上传，也要对完成率持续负责。陈宇森举例说，有些任务应该在运行 100 次时只错一次，甚至 1000 次只错一次；若一个智能体十次里错五次，它就不适合被当成商品继续售卖。评测、运行监控、评论和可能的退款，才构成交易成立的底座。

货架为什么不够，为什么又不能轻易放弃交易

双边市场的启动很难。创作者看到没有用户的平台，不愿花时间部署；用户看到稀疏的供给，也不会停下来寻找。MuleRun 正式上线后的几个月已经完成交易功能，接入了一些供给，注册用户也在增长，但团队没有看到足够多预期中的产品市场匹配。陈宇森把原因更多归到供给丰富度：创作与上架仍然依赖 n8n、LangGraph 等工具和人工环节，离普通人能顺手完成还有距离。

到第二次访谈时，团队已经把重心放到 Agent Builder。平台管理 Base Agent 和运行环境后，用户只要通过接近自然语言的方式描述任务，就可以构建能完成特定工作的智能体，并先分享给朋友。这不代表新产品已经得到大规模验证。内测刚开始一天，访谈里提到的主要例子仍是团队运营人员用浏览器自动做 KOL 调研，再把结果写入钉钉文档。它首先证明的是创作和分享的路径被缩短了。

“市场其实核心是该以分享为主还是交易为主。”

陈宇森，谈 Agent Builder 与 Marketplace 的边界

这道问题还没有答案。货架适合用户已经知道自己要找什么的情形，却不擅长接住一个模糊的工作问题。陈宇森想象的未来入口更像一次对话：用户先说想解决什么，系统能直接做就做；若某个创作者已做过更适合的智能体，就把请求路由给它；若没有，才引导用户创建。货架仍会存在，但会退到二级入口。

真正困难的是收益分配。传统 Marketplace 可以让创作者直接给商品定价；一次对话背后可能由多个智能体、技能和环境共同完成，怎样判断贡献、怎样为调用付费，团队仍在讨论。陈宇森并没有把这包装成已解决的商业模式，反而把它视为产品正在测试的关键不确定性。

桌面与云端，权限决定产品边界

Anthropic 发布 Claude Cowork 后，更多人开始注意到 Coding Agent 可以被包装为普通用户可理解的工作工具。陈宇森认为，这会让 Claude Code 是 General Agent 的认识更快成为共识。Claude Cowork 位于桌面端，可以接触日历、下载目录和本地文件；这让它适合整理文件、准备会议等任务，也意味着用户要把更多个人上下文交给它。

MuleRun 希望更多在云端做工作和效率场景。云端的好处是可以为一个智能体单独创建账号，只授予必要权限。它并不替代桌面端：本地上下文能做的事很有价值。两种位置只是面对不同的信任关系和任务边界。MuleRun 所要补的也不只是一个图形界面，还包括预置 Skills、运行环境与构建过程，把原先分散在多个工具里的配置放到一处。

连续创业后，他把方法收缩成用心

技术路线的转向背后，是一段并不平滑的个人经历。陈宇森 20 岁从浙江大学毕业后参与创办网络安全公司长亭科技。长亭在 2014 至 2019 年间持续成长，2019 年 10 月被阿里云收购。他在阿里工作近两年后重新创业，同时做游戏和数据安全。第一段创业的上升经历给了他很强的自信，也让他在进入陌生行业时低估了失败的必要性。

游戏公司做第一个项目时，团队想做有玩法和题材创新的 PC 游戏，融资也相对充足。后来项目失败，他关掉了游戏公司。回看这段经历，他认为自己太相信第一次就能做对，也同时承担了两家公司的复杂性。与其让融资规模推着团队去做一个更大的项目，他现在更看重选择与能力、认知相匹配的方向，并留出学习和失败的时间。

第二次创业走下坡路时，压力更具体：失眠、无法起床、对过去判断的怀疑，以及团队凝聚力的流失。关闭公司前，账上还有资金，但他认为自己已经没有足够状态，也不相信继续花钱会提高翻盘机会。朋友知道他的情况后，不反复劝说，只是约他去打游戏；这种陪伴和分心帮助他逐步恢复。

“就一定要用心”

陈宇森，谈自己如何区分认真完成任务与真正投入一件事

他所说的用心，不只是细致完成交办的工作，而是持续思考事情本身、亲自接收一线反馈。创业里的假设会不断被证明或推翻，产品需要据此调整。MuleRun 从货架式 Marketplace 走向 Agent Builder，正是他在访谈中给出的一个现场例子：发现供给没有增长到预期，就回到创作门槛和产品入口重新做判断。
