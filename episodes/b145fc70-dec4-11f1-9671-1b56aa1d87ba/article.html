「超声波货币」叙事失效后：以太坊、钱包与推理市场

嘉宾：Greg Markou（前以太坊核心开发者）；讨论者：Kain、Austin

圆桌讨论 协议与产品 市场结构

来源：Unchained · 2026 年 11 月 · 1 小时 16 分

这期 Uneasy Money 没有把以太坊的问题压缩成单一结论。Kain、Austin 与临时加入的 Greg Markou 从 ETH 的估值叙事谈起，接着讨论 gas 改价会怎样影响既有合约，又把视线转向硬件钱包的清晰签名、移动应用的托管体验，以及把 AI 推理做成链上市场的设想。话题不断切换，底下却有一个共同处境：协议规则、产品界面和价格机制一旦进入真实使用，就会碰到原先模型里没有写全的依赖与激励。

ETH 的价值如何说明

销毁机制曾给出一个易传播的故事，但投资者需要的不止是口号。

协议改动如何落地

gas 改价可以改善扩容，却可能触碰应用、代理合约和链下服务的隐含假设。

市场能否替代中介

推理供给的价格差创造了机会，也把隐私、履约和滥用风险一起带进来。

「超声波货币」把复杂协议压成了一个指标

讨论从 EIP-1559 开始。一位参与者回顾，在这项费用机制上线前，用户需要自己猜测 gas 价格，交易失败的体验并不少见；上线后，钱包更容易替用户完成这项判断。大家都承认，它解决了重要的使用问题。不过，其中销毁 ETH 的设计后来被提炼成「超声波货币」：供应减少，因而资产会更有价值。

他们并不否认这个口号在当时有效。以太坊的去中心化、安全性和可编程性很难用几秒钟解释，而资产叙事能够让更多人迅速记住它。问题出在口号开始主导讨论之后：社区出现了追踪销毁量的工具，话题也容易滑向如何销毁更多 ETH。几位讨论者认为，EIP-1559 的原始重点不是最大化销毁，而是在费用市场中处理激励与用户体验；如果扩容的目标是让交易更便宜，交易费究竟该不该被当成资产价值的核心来源，也就值得重新问一遍。

讨论者认为，ETF 等渠道带来的价格影响让这个问题更迫切。面向机构或公开市场的投资者，不能只重复供应收缩的说法，还要说明以太坊作为网络为何有价值、这种价值怎样与 ETH 相连。一方认为，创始人至少应能讲清人们为什么在乎他创建的系统；另一方则反驳，Vitalik Buterin 是首席科学家，不应承担公关、营销和游说的全部工作。分歧不在于是否需要解释 ETH，而在于谁来讲、应当讲到什么程度。

gas 改价碰到的，是一张难以穷尽的依赖网

随后，话题落到正在酝酿的 gas 重定价。参与者提到，某些操作例如 SSTORE 可能变得更贵，应用开发者担心成本结构会在自己毫无准备时被改变；他们还援引了 Kyber 团队对一个改动会破坏自动做市商的担忧。这里的矛盾很具体：协议层需要用价格反映资源消耗并继续扩容，应用层则已经围绕旧价格和旧行为部署了合约。

曾参与核心开发的嘉宾并不把这种摩擦解释为核心开发者不关心应用。他说，以太坊是一个庞大而单体化的系统，最难的工作常常是找出哪些不变量不能被破坏。测试网能暴露问题，却不能列出所有依赖。嘉宾曾在维护 Web3.js 时改动过与 EIP-1559 有关的部分，后来才发现 MetaMask 之间存在自己不知道的约束，结果影响到许多应用。过去的 gas 重定价也有类似经历：有些改动平稳运行，有些则改变了开发者原本依赖的行为。

增加测试案例也不能穷尽这类问题。另一位讨论者拿一个旧地址的分析作例子：一年内约九百笔交易会产生数千条事件，代理合约还可能在某个区块把预言机指向新地址。若要在分叉状态里重放一个 DeFi 协议，不只要读合约代码，还得配置链下程序、外部预言机和账户行为。AI 或许能帮助整理这些线索、提示硬分叉对应用的影响；重放结果仍取决于能否还原这些状态和依赖。

对核心开发者而言，持续涌入的 EIP、长期未结束的技术争论和安全边界本已消耗大量精力；对应用开发者而言，看到测试网出问题后尽早检验自己的协议，也不能完全交给别人。节目因此没有把责任归到单一一方：协议改动需要更早理解实际应用，应用也需要把即将到来的改动纳入测试。两边的工作都受限于系统本身的复杂度。

清晰签名需要什么信任边界

Ledger 的签名 SDK 引出了一场更尖锐的产品讨论。几位参与者根据自己查看的文档和 API 请求表示，SDK 会在签名交互中向 Ledger 的服务发送请求；他们尤其质疑一笔交易签名完成后仍回传的元数据，认为即使新版减少了字段，仍可能据此关联地址。他们的批评针对的是这种实现所带来的遥测和攻击面，而不是声称已经确认了服务端的具体用途。

Ledger 一侧在节目中被转述的理由是，硬件设备难以独自解析复杂合约调用，向服务器求助才能把用户真正要签的内容展示清楚。讨论者指出，若某个请求发生在签名之后，它就难以成为签名前安全检查的必要步骤；他们也认为，厂商早已知道清晰签名会占用资源，本可以在设备存储和预置常用合约信息上做更多准备。离线设备仍有其价值：有人承认，Ledger 等硬件钱包曾在防范中间人攻击方面保护过大量用户。

清晰签名本身也不是把一段 calldata 翻译成人话那么简单。节目提到，相关标准可以规定如何读取载荷，却不能替钱包决定每种合约怎样显示；链上注册表中的内容还要经过审核。代理合约、可变化的 ENS 地址和可插拔的合约模块都意味着，固件里写死的信息会过时。为了让用户看到准确的交易含义，钱包有时可能需要从一个或多个受信服务取得经过证明的数据。于是，争论的焦点延伸为：哪些数据必须离开设备、由谁解释、用户又如何知道解释没有被篡改。

钱包退到后台，应用把安全机制包进体验

几位参与者都觉得，如今把硬件钱包当作普通用户的主要界面并不理想。一个设想是把多签、每日限额、社交恢复和熔断机制放在智能合约账户后面；用户在手机上看到的只是 passkey 或面容验证。节目中的描述是，passkey 可以成为合约的签名者，合约再参与多签；设备丢失时可由恢复流程处理，恢复操作本身也保留撤销窗口。安全策略仍在那里，只是不要求每位用户先理解多签的所有术语。

这个设想也有成本。多签与恢复会增加状态和选择，向用户说明风险并不总是容易。更现实的阻力来自跨链：一条链或一个生态中最弱的托管与签名环境，往往决定了整个产品能给出的体验。讨论者还把 DeFi 原生应用迟迟未普及的一部分原因归于监管顾虑和应用商店的公司主体要求；若不重建整套界面，过去常常只能在移动端套一个 DApp 浏览器。

因此，他们预想用户为交易、借贷或预测市场打开不同应用，钱包能力作为嵌入式服务在后台运作。应用和嵌入式钱包团队随之成为新的集中风险点；一旦分析依赖或签名流程处理不当，便利也会扩大漏洞的影响。兼容多条链时应把多少资金留在数据库体系、多少坚持自托管，仍取决于具体链和应用的安全条件。

推理价格差会不会催生链上市场

最后一段从 MegaETH 的方向调整谈到 AI 推理。节目中有人转述其团队的设想：与其继续把重点放在原来的区块链用途上，不如利用链上结算与代币机制建立一个双边市场，让不同来源的供给方出售推理额度，需求方按价格购买。参与者认为，区块链适合记录交易和协调陌生买卖双方；GPU 不会在链上运行，推理仍需由链下 API 交付。

这套设想依赖一个尚未消失的价格差：实验室面向开发者的 API 价格，与个人订阅计划所能获得的使用额度之间存在差距。节目里的观点是，订阅制里本来就有使用很少的普通用户和尽量榨取额度的重度用户，后者可以把容易转手的推理额度变成套利对象。也有人提醒，嘉宾自己就是重度使用者，不能据此断定所有订阅计划都在亏钱。实验室持续调整 API 价格、额度和套餐，正是这个价差会被重新定价的原因之一。

价格最低并不自动等于适合所有工作负载。讨论者以 Venice 为例，提到其尝试把可信执行环境和保密计算用于隐私保护；即便如此，买家仍要判断自己的调用记录是否能暴露、供给方是否可信。开源项目的代码本来公开，可能更愿意选择便宜来源；处理专有代码或敏感问题的团队则有不同的风险。免费试用也会面临同样的可转售性与滥用压力，节目中有人转述一家提供短时推理试用的创业公司为应对盗刷而封禁整个国家的用户。

作者概括：从 ETH 的销毁叙事到 gas 改价、签名界面和推理市场，本期反复出现的是同一种约束：一个简洁的指标、接口或价格一旦接入真实网络，就必须面对它没有显露的依赖、信任关系和套利动机。每个场景都留下了具体条件，等待协议、产品或市场参与者处理。
