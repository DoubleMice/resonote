AI行业的收钱、花钱与赚钱

豆包尝试收费，表面上是一项产品定价，背后却连着一整套更难算的账：生成一次回答要花多少算力，用户愿意为什么能力付费，训练下一代模型的钱从哪里来，最后又是哪一层能留下利润。庄明浩、高飞和兰溪沿着这条线，从个人订阅谈到芯片、数据中心、模型公司和应用公司。

收钱
推理成本、订阅分层、广告与渠道。
花钱
训练、芯片、机房与长期资本开支。
赚钱
不同产业层的位置、成本和议价能力。

一次生成，就有一次成本

三位讨论者认为，生成式 AI 与过去很多互联网产品的差别，先体现在成本形态上。用户要求模型写一段文字、处理一张图片，或完成一次复杂的编程任务，模型都要针对这次请求重新推理。请求之间并不等同于复制同一份静态页面，Token 消耗会转化为算力支出。

月费订阅只能先按平均使用量设计。多数用户使用不多时，服务商能把重度用户的成本摊在整个订阅池里；当高用量用户越来越多，额度、限速和额外购买就会出现。这些设置划定了谁承担多少使用成本。嘉宾因此认为，免费服务可以存在，但不可能把所有高强度使用都无限包进去。

节目中的成本前提
服务一次用户不再接近零成本，定价就不能只围绕获客；它还要考虑每次推理、每类用户和持续更新模型带来的支出。

豆包收费在试什么

庄明浩并不意外豆包尝试收费。他把它看作一次用户规模足够大之后的订阅试验，而非字节短期缺钱的反应：豆包可以检验大众是否会为 AI 服务形成稳定的付费习惯。兰溪的看法更进一步：领先产品如果始终免费，后面的千问、元宝等产品就很难率先收费，因为它们会担心用户直接流向免费替代品。头部产品的价格动作，可能为整个市场打开或关上一段定价空间。

这也让讨论从是否收费，转到收费对应什么。兰溪在节目中以一张当时流传的豆包价目图为例，列出每月 64 元、200 元、500 元三档，同时明确说不清楚其后是否调整。这些数字不能当作现行价格，更有价值的是它们揭示的分层思路：轻度用户、追求生产力的人和高频创作的人，对模型速度、额度、最新版本和多模态能力的需求不同。

嘉宾还设想，付费层可以通过更早使用新版本、更多使用额度或更完整的音视频能力与免费层分开。日常搜索和闲聊用户未必需要最高的能力上限；有明确产出的高频用户则会追问，一笔月费究竟换来了什么。价格的重点在于，用户是否认可这组权益能完成自己的任务。

个人订阅

产品把能力包装成用户能理解的服务与权益，但必须管理重度使用带来的成本。

生产力场景

当模型帮助完成可衡量的工作，用户更可能把价格与节省的时间、质量和结果联系起来。

广告、运营商与免费供给

订阅不是唯一的收钱方式。节目讨论了广告，但没有把它看成现有广告系统的直接复制。传统广告常根据页面或搜索关键词匹配；对话式 AI 若把用户输入与广告关联，就会碰到输入脱敏、数据关联和监管压力。嘉宾认为，中国互联网擅长把服务做成间接付费，但这种能力不自动消除对话数据的处理难题。

运营商是另一种可能的渠道。兰溪设想，模型厂商可以让某个通信套餐包含会员权益，借运营商触达个人用户，把单独付款变成账单的一部分。对于模型厂商，这能扩大分销；对于运营商，这可能增加套餐价值。不过是否合作仍由模型厂商决定，它们也要衡量渠道是否会削弱自己和用户之间的直接关系。

免费 Token 的讨论同样没有脱离成本。庄明浩支持企业报销员工使用模型，也认为教育机构可以给学生提供使用条件，因为学习一项工具需要亲手操作。兰溪则提醒，普惠、盈利和服务质量很难同时拉到最高：如果只宣传巨量 Token，却不说明所用模型的能力，用户得到的可能只是便宜的调用量。学校和公司还要面对另一层问题，既担心成员不用 AI 会脱节，也要重新处理作业、评估和工作流程。

订阅收入无法独自覆盖下一轮训练

收钱之后，问题随即变成花钱。庄明浩把当下的投入放到芯片、数据中心、电力和建设速度的物理条件里看。科技公司能够写下很大的资本开支预算，并不意味着芯片产线、原材料、机房建设和电力接入能在同一时间扩张。训练和部署规模上去后，供给侧本身会成为约束。

节目把模型公司粗略分成三种资金结构。拥有成熟主业的大型平台，可以用既有现金流支持 AI 投入；独立模型公司需要依赖巨额外部融资争取研发周期；订阅、API 和其他用户收入则开始检验真实需求。现实中的公司往往同时使用这些来源。它们的区别不在于哪一种更纯粹，而在于面对长期训练、机房建设和短期收入波动时，谁有更长的承受时间。

成熟主业
为长期投入提供已有业务的现金流。
外部融资
为尚未成熟的模型业务购买研发时间。
用户收入
订阅和 API 验证服务是否有人持续使用。

竞争尚未出清，不等于没有成本

为什么中国市场里仍有不少模型和视频生成公司？兰溪的解释是，竞争还没有迅速形成绝对断层。只要总市场继续增长，位于前列之后的公司仍可能获得融资、增长收入或进入资本市场的机会。它们不一定需要立刻超过所有对手，投资人也会押注市场还没有完全定型。

他把美国描绘成另一种压力更强的环境：头部公司一旦跑得太快，落后者会更难拿到持续投入所需的资源。这个比较是对竞争节奏的观察，不是两国市场的固定定论。它仍保留了一个共同条件：无论竞争格局暂时多么开放，融资热度和上市窗口都不能替代单位成本、产品优势和现金流。

订阅与 API 会同时存在

订阅面对的是直接使用模型的人，API 面对的是把模型接入产品和企业流程的开发者。前者需要把能力翻译成用户能感知的权益，后者让模型能力沿着下游软件、Agent 和业务系统继续传递。两者不是互相排斥的选择，一家公司也可以同时依赖它们。

嘉宾没有为未来比例给出一致答案。庄明浩认为，中国的个人用户市场相对强势，若个人直接付费能跑通，订阅占比可能更高；美国积累多年的企业软件和 SaaS 生态，则更利于 API 在企业应用中扩散。他们真正一致的地方是，若 AI 应用迎来更广泛的增长，调用模型的 API 需求会随之增加。收入结构最终仍取决于公司已有的用户基础、企业生态和具体产品。

订阅解决什么

把复杂模型能力变成个人或小团队愿意按周期购买的服务。

API 解决什么

让下游产品和组织把模型能力嵌进自己的工作流、界面和交付中。

谁在产业链上先赚钱

主持人用一套五层框架组织问题：电力、芯片、基础设施、模型、应用。庄明浩的判断是，当前更接近收入端的是芯片与基础设施供给方；他以英伟达和台积电说明，模型训练和推理扩张时，上游设备的需求最先被看见。数据中心的情况更复杂，业务需求不代表财务报表轻松：为了扩建而借入的资金和利息，会在相当长时间里压着当期表现。

模型层处在中间位置。嘉宾认为，如果把预训练新版本的投入暂时拿开，已经上线的推理服务有可能覆盖自身服务成本；可模型公司不能因为一代模型服务有收入，就停止训练下一代。竞争要求它们继续投入更大的训练和基础设施，原本可能出现的利润又被带入下一轮资本开支。

应用层的压力最贴近用户。应用要为模型和云付费，还要承担获客、投放、运营和转化成本；上游能力变强时，应用未必能同步提高收费。嘉宾没有据此否定应用的长期机会，只是认为现在很难把所有成本都传给最终用户。市场随后会追问一个更具体的问题：模型调用和编程辅助带来的产出，是否足以覆盖增加的投入。

节目中的利润分布
上游供给方的需求较直接，模型需要在服务收入与持续训练之间周转，应用则必须把技术能力变成用户愿意持续购买的结果。

中美的账，先受电力和产业条件影响

在比较中美商业化路径时，庄明浩先谈电力。他认为，中国电力体系的运营方式和既有建设成本，与美国更多由私营企业运营的电力市场不同。数据中心扩张会在两地遇到不同的电价、接入和公共压力，因此同样的算力项目并不处在同一套成本约束之下。

芯片是另一个不对称之处。庄明浩承认中国与英伟达、英特尔、AMD 等公司的先进芯片能力仍有代际差异，同时认为成本、资源调配和产业组织方式会影响这段差距对下游模型公司的影响。到了模型层，他预期中国会出现更多不同方向的参与者；到了应用层，他期待更丰富的产品尝试。这里谈的是市场条件和可能的分工，不是已经兑现的商业成绩。

兰溪补充的视角是经济性与稳定供给。他认为，中国的模型产品可能不会只沿着效率和回报率竞争，也会尝试陪伴、购物、出行等更贴近消费体验的形态。是否能直接赚钱仍需验证，但产品玩法的多样性本身会影响商业化如何发生。

硬件把商业化带回试作现场

节目结尾回到硬件。庄明浩认为，中国的潜在优势在于供应链、制造经验和做样品的速度：一个设备想法可以较快从概念变成可试作的产品，AI 则给原本功能有限的硬件增加更聪明的控制能力。他提到玩具、学习设备、宠物设备等方向，正是因为这些产品能在较短周期里反复试验。

这个过程不会只产出成功产品。庄明浩也承认，市场会出现不少看上去奇怪或不成熟的设备。但从一个想法、一个小样到可能上市的循环足够快，才让更多团队能检验需求、成本和交付。对本期的收费、花钱和赚钱三道题来说，最后仍要落在这里：产品能不能做出来，用户会不会持续使用，收入能否覆盖下一轮投入。
