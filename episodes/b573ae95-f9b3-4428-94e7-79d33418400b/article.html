从机房开始，工程师先学会解决问题

唐文斌在浙江新昌长大。初二时，学校刚开始组织编程竞赛，他和同学一起拿到机房钥匙。有人把机房当作打游戏的地方，他和另外两三个人却发现，写程序更有意思。对他来说，编程的吸引力来自一个明确的闭环：问题摆在面前，自己设计方法，写成代码，再用测试结果确认方法是否有效。

这种训练和数学、物理竞赛不同。编程题往往没有唯一解，程序还可以继续优化。参赛者会在提交结果后马上获得反馈，下一轮思考因此有了具体依据。唐文斌后来做竞赛出题，也看到了另一面：做题可能只用一两个小时，设计一道能拉开约 200 名参赛者分数的好题，却可能要花一周。

这段经历解释了他为什么会把创业理解成工程工作的延伸。创业并没有先给他一个完整的市场答案，而是让他自己选择问题，再承担产品是否真的有用的结果。

创业的第一步并不清晰

唐文斌、印奇和杨沐在清华读书时都做过图像相关的研究。他们当时谈的是计算机视觉和机器学习，还没有今天常用的 AI 叙事。三个人觉得机器人未来需要眼睛，因此视觉技术会有长期价值，但他们并不知道应该从哪一种产品开始。

2010 年前后，Kinect 让体感游戏受到关注；iPhone 4 的前置摄像头又给手机带来了识别人脸和动作的可能。三个人先用自己的 MacBook 做了体感游戏乌鸦来了，后来又做了街头速滑。乌鸦来了一度进入 App Store 免费榜前三，也让投资人主动找上门。

游戏带来了名气，却没有让他们找到长期兴趣。三个人并不真正关心小游戏的策划、收费点和数值设计。2012 年年中，他们停掉游戏开发，把计算机视觉能力放到 Face++，让开放 API 帮助他们寻找更有价值的应用场景。创业的方向感是在行动中逐渐形成的。

Face++ 把技术带进了真实需求

开放平台早期承载着探索功能。美图秀秀和美图手机使用过 Face++ 的人脸关键点检测等能力，用户能看到瘦脸、放大眼睛等效果，但这类 SDK 业务还没有形成很强的长期门槛。

支付宝建设浙江网商银行时，在线开户需要确认用户身份，也需要足够可靠的人脸识别。唐文斌回忆，当时行业在 LFW 人脸识别评测上的结果大约处于 90 到 91 的区间，旷视采用深度学习后把结果推进到 98 到 99。技术结果在这个场景里变成了金融身份认证的业务价值。

范浩强和周而进的故事也发生在这个阶段。团队让一名高中生先试深度学习，范浩强和本科生周而进组成的强进组合，改善了从关键点检测到人脸识别的多项能力。技术路线尚未形成共识时，年轻成员的动手速度给了公司一次重要的试验机会。

数据飞轮才可能把技术差异留下来

唐文斌把纯技术优势和长期壁垒区分开。一个算法结果领先几天，竞争者可能很快跟上；如果产品被更多人持续使用，它就会积累更多数据，帮助算法继续变好，领先才可能变成循环。

身份认证是这个循环的例子。支付宝之后，滴滴、Uber 和其他互联网金融及线下服务场景也有身份确认需求。平台见过更多用户，系统获得更多真实信号，客户又有理由继续使用它。

这也说明了为什么所有技术业务都不适合用同一套商业判断。客户对普通 SDK 的精度要求可能没有那么高，竞品容易在时间差里追平；身份认证则把规模、准确性和信任连接在了一起。

To B 的三条经验，最后都指向可复制

第一，客户价值必须能算。客户需要知道产品解决了什么问题，降本或增效如何体现在真实数据上。把数字写进一份漂亮的 ROI 文档，却无法在续约和复购中得到验证，业务很难长期扩大。

第二，供应商最好不要在客户成本构成里占据过大比重。客户会权衡自研和采购，如果供应商的能力没有强到难以替代，成本占比越高，自研动力就越强。宁德时代和英伟达之所以能承受更高成本占比，前提是客户暂时仍然需要它们的能力。

第三，团队要防止每个客户都变成一个新项目。旷视在物流业务里把仓库拆成入库、托盘存储、箱式存储和发货等环节，为每个环节提供标准产品，再让集成商组合方案。客户现场仍然有差异，但差异被控制在配置层，产品才有机会复制。

仓库是机器人进入物理世界的起点

唐文斌和印奇去天津天猫超市仓库时，看到拣货员在零下十度的环境里工作，每天大约走四十公里。仓库人员一年流失率被说成 200%，这不是一个单纯的工资问题：岗位很累，招人很难，管理也很复杂。

仓库之所以适合作为机器人起点，还因为处理对象相对标准。托盘、箱子和单件商品让团队有机会把场景拆解，再用调度系统安排机器人的路线、订单优先级和协同关系。真正决定系统效率的，往往是多台机器怎样一起工作。

旷视在 2016 年左右布局机器人业务时，团队并没有能力直接做通用机器人。物流提供了一个可以先用起来的盒子，也给了他们把视觉、运筹和强化学习方法放在真实系统里检验的机会。长期目标则是让机器人走出这个盒子，进入更开放的环境。

优衣库项目说明了真实交付的重量

2019 年上海优衣库仓库项目经历了五轮提案和筛选，最终需要部署上千台机器人。旷视在竞标时强调软件和算法对整体效率的作用，客户也认可调度能力是复杂项目的关键。

项目同时暴露了 To B 竞争里的风险。供应商为了拿到订单会提高承诺，客户的期待因此超过了当时的技术水平。旷视最初完成系统后，目标效率是 100%，实际只达到 40%。客户给了团队半年的延期时间，团队把全部 code 推倒重来，最后才把项目做成。

这段经历改变了唐文斌对信任的理解。供应商还没有建立权威时，直接说做不到可能会失去订单；建立信任后，团队就可以把风险说清楚，和客户一起做小规模实验。对于具身智能，失败之后怎样接管，也必须在工作流里提前设计。

原力灵机把问题重新放回模型

旷视原有的物流机器人业务后来形成了相对成熟的搬运产品、客户和渠道体系，相关业务也形成了单独的元灵聚合机器人（Atomix）。2024 年，团队开始尝试用大模型驱动机器人控制，并开展 RL 相关实验。原力灵机在 2025 年春天开始正式运营，重组交易在此前持续了几个月。

新公司目前约有 100 人，约 40% 来自原来的同事，约 60% 是新成员，并预留了 30% 期权池。老团队愿意继续合作，原因既有十多年配合形成的信任，也有物流客户和真实场景的积累。高人才密度能提高研发配合，却不能自动解决客户洞察和交付细节。

唐文斌把原力灵机的核心问题归结为模型和大脑。机械臂、摄像头和其他硬件已经能完成不少事情，机器人是否真正有用，取决于它能否理解任务、完成操作，并在能力不足时保持可靠。智能、有用、可信赖因此成为同一套产品要求。

具身原生，意味着数据从第一天就进入模型

现在常见的 VLA 路线，是先训练好一个 VLM，再在后面加 action 模块。唐文斌担心，这种嫁接式训练可能让动作能力变强，却损伤原本的多模态能力。他更倾向于在 VLM 预训练阶段加入机器人数据，再在 VLA 阶段同时训练 grounding 和 VQA 等能力。

原力灵机和阶跃共同训练 DM0 时，把多模态互联网数据、自动驾驶数据和机器人操作数据放在同一条训练路径上，先形成原生多模态 VLM，再继续训练 VLA 并进行 post-training。这个方案成本可能更高，但它试图让模型从一开始就接触物理世界。

数据采集仍然有很多未解问题。团队当前以真机数据为主，使用遥操作、手部设备、外骨骼和以人为中心的穿戴式设备。仿真数据在 locomotion 和高层任务规划上更有帮助，但接触丰富、涉及非刚体、力觉和触觉的操作仍然很难仿真。

三层系统连接模型、硬件和场景

唐文斌把具身系统拆成三层。System 2 处理慢速思考、任务理解和规划，大语言模型在这一层已经有很强能力；System 1 由 VLA 处理中频动作；System 0 处理力觉、触觉和更细的高频控制。三层之间如何传递信息，仍然没有标准答案。

硬件也不能只靠模型来决定。遥操作先回答一个底层问题：人使用这个本体是否能完成任务。如果人也做不到，模型无法越过硬件的精度、负载和形态限制。进入具体场景后，低重心 AGV、机械臂、传感器和末端执行器可以按任务组合，过度设计会直接推高成本。

更适合当前落地的场景

场景允许犯错，有人工接管；节拍要求不过快；任务需要适度泛化；机器人可以长时间作业。

物流的系统答案

机器人先执行，失败后由调度系统把任务交给人工工位或远程人员。客户核算的是整套工作流的总成本。

这套设计把具身智能从单机演示拉回生产系统。机器人不必一次完成所有任务，但整条流程必须连续工作，客户也必须看见真实的经济结果。

开源基础设施，服务的是迭代效率

原力灵机把 DexBotic 做成建在 PyTorch 之上的工具箱，为 VLA 和模仿学习提供统一配置、数据格式、训练和部署工具。RoboChallenge 则用真实机器测试算法，让团队知道哪条路线在进步。两者原本都服务内部研发，后来被开放给行业。

唐文斌认为，模型当前状态会不断交换领先位置，真正重要的是让数据、训练、推理、硬件和评测连接起来，持续提高迭代速度。公开代码和评测也会增加信任，同行可以复现结果，社区的使用和贡献还能反过来改善工具。

旷视早期做过 MegaEngine，直到 2018 年才开源，已经错过了建立生态的时间。这个教训让原力灵机更早开放基础设施。开源并不消除竞争，它把竞争从一次榜单排名转向谁能更快地把能力推进到真实应用。

行业会先分散，再逐步集聚

在模型尚未统一时，许多公司可以围绕不同 vertical 场景生存。模型能力增强后，小模型和单一场景的空间会逐渐收缩，平台型公司可能把模型、本体和场景重新组合。唐文斌判断，长期可能只剩个位数的全球平台型公司，而且中国公司在硬件迭代和供应链协同上有更明显的优势。

原力灵机因此拒绝表演路线，也谨慎看待汽车产线。汽车场景的错误容忍度低、节拍要求高，虽然展示效果容易被看见，却未必适合当前模型。团队更愿意寻找可以让人工兜底、让机器人长时间运行的场景。

他给行业的提醒很克制：技术突变可能需要时间，团队既要准备足够资金，也要把资源集中在真正相信的模型和场景上。2026 年的目标被压缩成两件事：提升 multi-task 和 generalist 模型的成功率，并在一个真实场景里让 1000 台机器人持续使用。这个目标把长期模型能力和阶段性商业证据放在同一条数据飞轮上。
