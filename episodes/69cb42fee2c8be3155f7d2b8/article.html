AI 产品 战略 访谈 投资

这期串台录于 3 月初。开场时，庄明浩回头听录音，感到一个月内的行业变化已让当时的讨论像隔了很久。节目没有试图给下一轮热点排座次，而是借 Open Claw 的走红，拆开几个更实际的问题：为什么一类 Agent 会突然让普通人有感，怎样才能把它真正接进日常任务，以及模型竞争究竟卡在什么地方。

谈话里既有兴奋，也有大量没有结论的地方。庄明浩不把 Open Claw 说成凭空出现的技术飞跃；他同样不认为下载一个工具就等于进入了 Agent 时代。权限、账户、工作流、模型能力和评价标准，都会在后面反复出现。

Open Claw 为什么让更多人感觉到 Agent

庄明浩把 Open Claw 看作一次工程上的重新组合。让 AI 操作电脑、调用工具或读取文件，并不是突然出现的想法；此前不少 Agent 产品已经在虚拟机里完成过类似尝试。这次的差别在于，它把这些能力放进了更贴近日常的交互层。它可以待在飞书一类即时通信工具里，用户不必专门打开一个陌生的网页或应用，便能像交代同事一样发出任务。

这种变化对熟悉编程和多种 AI 工具的人未必惊人，对较少接触 Agent 的人却很直观。再加上项目开源，安装、改造和围绕它延展功能的人一下子多起来，使用经验和想象也更容易传播。庄明浩把技术发展、用户体感和这个时间点的传播条件放在一起看，因此没有把走红归结为某一项模型能力。

真实环境 任务会碰到文件、浏览器、账户和权限，而不只是在对话框里生成一段文本。
熟悉入口 即时通信工具降低了使用时的切换感，也让 Agent 看起来更像持续在线的协作者。
开源扩展 更多人可以围绕基础项目继续制作工具、界面和新的连接方式。

能运行，不等于可以交给普通用户

庄明浩讲了自己的一个小任务：朋友送给他一张智能眼镜优惠券，但商品长期缺货，而优惠券有期限。他希望 Agent 每天早上查看一次库存。这个任务本身很简单，实际配置却涉及商城账号、浏览器访问、执行时间、通知频率以及飞书机器人权限。等到任务稳定运行之前，他还要和 Agent 反复确认要求。

他先在云端尝试，后来才把 Open Claw 放到闲置笔记本上。本地部署并非为了宣称它更安全，而是为了在涉及账户、本地浏览器和文件时，获得更强的掌控感。与此同时，本地方案也把模型接口、系统环境和权限设置留给用户自己处理。他在 Windows 上安装时反复遇到教程跳过的细节：教程制作者已经走通的步骤，对第一次操作的人可能需要等待、排错和重来。

云端试用

庄明浩建议刚接触的人从这里开始。成本和操作负担较低，适合感受完整流程。

本地部署

更贴近用户自己的设备与数据，也要求用户承担接口、环境和权限的配置工作。

这也解释了为什么有人愿意为上门安装付费。把现成工具接到飞书、下载技能或补齐配置，看似是在减少门槛，却同时引入了来源、权限和凭证保管的问题。庄明浩提醒，用户不必等到有人故意植入恶意程序才会出事；安全意识不足、将敏感信息暴露给可联网的 Agent，本身就可能造成风险。

权限、性格与社交关系都还在试

当 Agent 开始替人浏览、发帖或联系别人，产品边界不再只由传统软件的固定规则决定。庄明浩的说法是，大语言模型与把条件写死的程序不同：人很难预先列出每一条围栏，更难让每个人都满意同一条边界。用户可以给它设偏好和表达风格，但它实际做了什么，在使用初期仍值得查看。

节目由此转到 AI 社交。AI 可能是工作分身、性格分身、用户理想中的另一个自己，也可能是一个独立的角色；不同定位会导向不同的产品。人与 AI、人与 AI 再与人、AI 与 AI 之间，都会形成新的关系结构。庄明浩没有把其中任何一种说成正确答案。到录制时，中国和美国都还没有出现能够为 AI 社交下结论的产品形态。

节目保留的限制：对外行为、个性设定与社交关系不是同一件事。一个能执行任务的 Agent，未必适合代表用户在公共空间行动。

开源项目可以长出更多层，但方向并未固定

庄明浩举了几个围绕 Agent 延展的想象：有人为它制作可视化办公室，让用户在桌面上看到它工作或休息；有人设想让多个 Agent 出现在同一界面里互动。这些例子没有构成统一产品路线，却显示了开源的一个效果：基础项目开放后，别人可以继续补上界面、工具、认证、支付或互动方式。

他把这与早年 Web3 描绘过的层次作类比。那套叙事曾把协议、认证、支付和交互放在同一张图里；现在，若 AI 要作为行动者参与互联网，许多原本主要为人设计的接口也许需要重新考虑。节目并没有把这条类比推成事实，更提到相关创始人未必愿意触及代币等金融叙事。它只是说明：Agent 的热度已经把讨论从一个软件推到了周边基础设施。

提示词的作用，是把任务范围收窄

主持人问怎样学会提问，庄明浩没有把答案收在某个提示词模板里。他用补全来解释模型：给出相近、明确的条件，模型需要填补的范围较小；条件相距很远，结果就可能落在很宽的区间。这是他理解提示词、技能和流程设计的共同出发点。

复杂任务因此要被拆开。用户需要说明每一阶段做什么、接收什么、交出什么结果，人与 AI 分别负责哪一步，以及怎样验收。庄明浩听到内容团队的工作流时，特别在意这些交接是否已经稳定；模型只是其中一环。模型可以处理自然语言，但不会替用户天然做出合适的任务定义。

他用 AI 漫剧说明这种差别。视频模型能力提高是必要条件，行业里可复制的部分，是剧本、分镜、文字转图片、图片转视频、导演检查等环节逐渐被排成可执行流程。主持人曾用同一段提示词生成视频，得到的结果彼此差异很大；庄明浩认为，提示范围、镜头理解和模型的一致性仍需要更多外部约束。流程把波动留在可检查的位置。

定义目标 说明要做什么、需要哪些输入、期待什么交付物。
分段交接 将复杂工作拆成能判断对错或取舍的阶段。
保留验收 输出进入下一步之前，仍要由人检查、选择或调整。

模型的风格与赛道，都在发生融合

主持人描述自己使用不同模型时感到的性格差异。庄明浩认为，这种体验并非全是错觉。预训练之外，后训练会让团队对输出进行打分、反馈和选择，模型因而带上不同的偏好；长期使用中的记忆和用户反馈，也会继续塑造个人体验。这里的偏好指训练与使用中形成的回答倾向，能解释为什么同一任务在不同产品上可能呈现不同回答方式。

在公司策略上，庄明浩提到智谱侧重编程、Kimi 侧重 Agent、MiniMax 长期投入多模态。到录制时，他觉得语言、图像、音频、视频与 Agent 已经不再是几张彼此独立的桌子。比如，让模型制作一张围绕某篇文章的信息图，前提是它能找到材料、理解文字、归纳信息，再生成视觉结果。这个任务天然需要多种能力共同参与。

这并不表示所有厂商已经达到相同水平，也不能由此推导出某个 AGI 时间表。庄明浩专门指出，行业甚至没有统一的 AGI 判据。即使用历史数据截断来测试模型能否独立得到新发现，也难分清结果来自真正推导、提示引导，还是资料中已经存在的线索。用覆盖多少场景或替代多少工作来衡量，同样会遇到定义问题。

算力是用户能感到的压力，数据是厂商更在意的差异

节目把模型竞争拆为算法、数据和算力。庄明浩认为，底层算法的重大突破难以按时间表预告；成熟公司会持续做改进和优化。用户更容易直接感到算力：新工具走红后，排队、限量和服务压力会迅速出现。一个 Agent 运行复杂任务，尤其要操作原先为人设计的应用时，消耗的资源并不小。

对模型公司，他更强调数据带来的边际差异。广泛、独特的数据不自动等于更好的模型，模型表现还受许多环节影响；但缺少这类输入，会限制厂商参与竞争的空间。算力又受芯片、电力、建设周期和跨境限制等现实因素影响，因此它既是技术问题，也不只是技术问题。

用户侧

等待、价格或使用限额，是算力约束最直接的表现。

模型公司侧

算法、数据、算力彼此牵连；庄明浩认为数据会带来更长期的差异。

从模型到可用产品，仍有一整层工作

主持人把套壳理解为在 API 外面加一层界面，因此担心它容易被模仿。庄明浩承认，狭义的简单包装可能只有短暂窗口；他也把概念拉宽：模型要被普通用户使用，就需要交互、流程、账号、权限和安全设计。以这个角度看，产品层并非天然没有价值，而是要看它是否真的让用户更容易完成任务。

这套判断同样适用于游戏、社交和内容生产。节目没有说所有行业都能被同一种方式重做。AI 可以在某些环节降低成本、提高效率，但一个行业长期存在通常有具体原因；新技术进入后，该改哪一步、该做到什么程度、用什么指标判断，仍要逐个场景摸索。庄明浩提到，AI 游戏的早期团队也只能先加上足够多的限定条件，做出一个范围清楚的小产品，再逐步调整边界。

项目变得更快，判断项目的尺子却还不稳定

庄明浩从投资角度补了一层变化。过去给团队一笔钱、等待半年到一年、再按里程碑决定下一轮投入的节奏，在 AI 领域未必总能适用。一个团队可能连续试验多项功能，几天后又发现原来的方向需要调整；他认为，项目的波峰和波谷会比过去更密集。更短的观察周期不等于可以放弃判断，它只是让问题更集中地落到团队到底在试什么、每次试验留下了什么结果。

AI 游戏让这种困难更明显。主持人提到用户量很大的产品，庄明浩反问，用户增长是否仍是这个时代足够的指标。节目没有给出替代口径。较早能看见的往往是降本增效：一项能力是否减少了某段生产成本，实施路径和投入回报能否算清。这类结果更容易检验，却未必是市场最兴奋的那个故事。行业口号可以解释为什么开始尝试，不能替代对具体场景、成本和产出的判断。

庄明浩的投资视角：快速变化要求更短的观察刻度；它不保证每次试验都有价值，也不提供通用的项目筛选公式。

从重复任务开始，把 AI 当作工作台

节目最后回到焦虑。面对行业叙事、职业变化和教育问题，庄明浩没有给出投资标的或技能清单。他认为更现实的做法是先在线体验，不急着把早期工具装进自己的全部生活。若有一件工作、生活或娱乐中的事情一周反复出现多次，就可以观察 AI 是否能在其中一个环节减少等待、整理信息、辅助记录或补足步骤。

这个建议的重点不是让 AI 替人做最后判断。任务要有明确目标，过程要有交接，输出要保留检查。审美、经验、直觉和任务拆解在节目中多次出现，但它们没有被说成万能护城河；关于社交、教育和未来工作如何变化，嘉宾明确承认尚无成熟结论。能立刻实践的，是把工具放进一个具体流程，看看它实际改变了什么。
