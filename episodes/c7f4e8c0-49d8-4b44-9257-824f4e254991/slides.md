# 为什么离开星海图

<div class="text-sm leading-relaxed">

- 家庭机器人的想法一直没变："那条**松鼠桂鱼**我也反复提过很多次"

# 造一个人，不是造一台机器

- "机器人其实只是一个**铁疙瘩**，它里面有电机，有它的结构件，有它的一些电路"
- 真正发生变化的，是里面的智能——让它能做各种各样的事
- 长期愿景："尽管我们现在是家庭机器人，但最终我们是想造一个人"
- 同一个机器人：下班后在酒吧跳舞、在田里种地、在课上教书
- "如果它是专门干那件事的人，我觉得人形机器人很难算得过来"

# 发散调研①：备菜机器人，没人买得起

<div class="text-sm leading-relaxed mt-2">

- 习惯"先发散再收敛"：给中美同学打电话，问愿为备菜机器人花多少钱
- 中国同学：备菜很重要，愿付**冰箱的钱**（约 1 万 / 6000 元）
- 美国同学：喜欢备菜过程，只愿付**高压锅 / 电饭煲**的钱（约 200 美元）
- 算账：一个关节约 1000 元，机械臂要 **7 个关节**——成本直接超预算
- 结论：在成本大幅下降之前，"某某机"一定不是机器人

# 发散调研②：工厂里其实不需要人形

<div class="text-sm leading-relaxed mt-2">

- 跑了车厂生产线、物流厂、鞋厂、食品工业、布草间
- 嘴上说"太需要人形机器人了"，细聊发现："在乎的不是人形机器人，在乎是能不能把那件事干了"
- 真正需要的是"**稍有智能的机械臂**"，而且对节拍、精度的效率追求非常极致
- 关键发现："那些非常高价值的事情其实已经都被自动化了……那些特别困难但是价值不高的事都留给我们了"

</div>

<div class="mt-4 p-3 bg-orange-50 border-l-4 border-orange-500 rounded text-sm">

**推论**：专门去解决低价值难题，会花掉大量精力却长期"打不正"。这件事应该由一个通用的东西**降维**去做。

</div>

# 结论：通用降维，先家庭后毛细血管

### 先通用

</div>

<div class="p-3 rounded bg-green-50 border-l-4 border-green-500">

</div>

<div class="p-3 rounded bg-yellow-50 border-l-4 border-yellow-500">

### 算得过来
通用意味着边际成本被摊薄：一个机器人的算力服务所有场景，账才成立。

</div>

<div class="p-3 rounded bg-purple-50 border-l-4 border-purple-500">

### 改变生产力结构
到那时不是"单纯的降本增效"，而是"所有的生产力结构都会发生改变"。

# Agent：把缝隙填上的能力

<div class="text-sm leading-relaxed mt-2">

- 家里有洗衣机、冰箱、微波炉……每一个都是专用的，中间"靠一个东西叫人"来串
- 家里不是流水线：冰箱没有出口，按个按钮就吐东西到微波炉
- Agent 让这件事变得可能：给一个"模糊的意向"，它主动去做
- computer use 的物理版就是"**厨房use**"：上传小红书、管理飞书日历都交给它

<div class="mt-4 p-3 bg-blue-50 border-l-4 border-blue-500 rounded text-sm">

"你再也不用说OK，帮我把昨天剩的锅包肉拿出来热一下……然后它就都搞好了。它就不再是一个什么什么机器，而是一个人。"

</div>

# AI Native：三条老路都不通

- 与 Erik Zhang（1X 前首席科学家）的共识：具身需要 **AI native**，之前的路径一直是错的
- "不是传统的机器人学，not robotics"——不要逐个解决困难任务，"**任务无法穷举**"
- 也不是自动驾驶：小场景数据闭环的路，在他看来做不出来
- 也不是史前深度学习：小模型堆叠永远不等于大模型
- 正路只有一条：统一大模型 + 全部数据 + 规模化后训练

# 不是传统机器人学

<div class="text-sm leading-relaxed mt-2">

- 传统机器人学喜欢"超级酷，但是只能解决这一件超级酷的事儿"
- 极致就是翻跟头、武术、跳舞；再往前是陀螺平衡、机械臂倒酒不洒
- 库卡的广告：好几个机械臂组乐队，打架子鼓、弹贝斯——"都是编程好的，很酷炫"
- "它肯定不是通用的physical AGI的那条路"

<div class="mt-4 p-3 bg-blue-50 border-l-4 border-blue-500 rounded text-sm">

**作者概括**：传统机器人学也可以上深度学习，但它是"一个个小模型针对单独的任务去学"——脑回路与大模型路线不同。

</div>

</div>

---

# 不是自动驾驶

<div class="text-sm leading-relaxed mt-2">

- 自动驾驶的思路：重视**数据闭环**，把一些路段跑得足够好
- 具身化的推演：先搞定五道口，再中关村，再海淀区，一块一块铺
- "我先解决一件小事儿，获得一些这件小事的数据，然后期待第二件事……我觉得是做不出来的"
- 大模型的启示恰恰相反："大模型就是把所有的数据放在一起"

<div class="mt-4 p-3 bg-orange-50 border-l-4 border-orange-500 rounded text-sm">

**注意**：行业里不少具身创始人来自自动驾驶背景，但他认为这只是个人判断，不代表他们会路径依赖——他只是认为这条路"做不出来"。

</div>

</div>

---

# 不是史前深度学习

<div class="text-sm leading-relaxed mt-2">

- 深度学习小模型一定程度上也是端到端，像"新时代的robotics"
- "你永远不要指望一个小模型叠加一个小模型叠加一个小模型叠加一百个以后，它等于一个大模型"
- 搬砖可以小模型：只做一件事，OK；要通用智能，"小模型一开始就走错了"
- 行业分歧的根源：相当一部分人"不相信physical AGI会诞生"，觉得它只是人形机械臂

<div class="mt-4 p-3 bg-purple-50 border-l-4 border-purple-500 rounded text-sm">

**scaling law 不等于数据多**："在一个固定的封闭的环境里面采再多的数据也没有任何用处"——案例类型不够多，归纳不出正确结论。

</div>

# AI 是一个归纳器

- "AI本质上是一个归纳器"
- 只看过大人用水杯，它会归纳"人都要用水杯"
- 看到宝宝一直喝奶、从不用带把的马克杯，它才修正为"有的人用、有的人不用"
- 案例越多样，归纳越准确——**多样性**很重要

# 多样性不能后补

<div class="text-sm leading-relaxed mt-2">

- 结论一旦归纳出来，很难再被新数据改变——"至少会带来巨大的痛苦"
- 所以"本质上那你最开始就应该把所有的数据放在一起"：预训练阶段就要全量多样
- 有人不信 scaling law 的全面版，觉得"等于我有很多很多的数据"——这是误解
- 一个做传统机器人优化的朋友，用了 OpenClaw 之后开始动摇对可解释性的坚持："即使是炼丹师，能做到这个程度，我已经认了"

# 模型路线：统一模型 + 规模化后训练

- 动作相关的部分"会是一个统一的模型"："没有办法通过做一百件事儿然后领悟到一千件事儿"
- 别人的后训练：收敛到单任务；破壳要做"**规模化的后训练**"——之后仍保持泛化性
- 强化学习三块：探索产生数据、**评估数据**、用好数据——被低估的是评估
- "那些坏的数据会使你的策略劣化"，次优数据要给评分、失败数据也要用起来
- 初期每个任务都平庸没关系：这是训模型的循序渐进，"再过一年它会变得在所有上面都很完美"
