# 中文文章结构与表达审查

本轮检查生成 prompt、文章校验契约，并抽读近期 FDE、唐文斌创业与具身智能、美国内战三篇成稿。全库模式检索覆盖 230 个 `article.html`，不代表逐篇完成语义或事实审查。改动落在生成规则和编辑流程，既有文章没有批量重写。

## 发现与优化

| 问题 | 仓库证据或成稿例子 | 本轮优化 |
| --- | --- | --- |
| 长文套用演示文稿结构 | 两份 prompt 都强制概览 4–6 卡、正文 8–12 节且每节 2–4 段、末尾 4–6 条金句；226/230 篇出现“核心金句” | RULE 10 统一负责文章结构，取消这些配额；引文随论述出现，概览与卡片按需使用 |
| 正文之前先复述所有主题 | 188/230 篇的 h2/h3 命中“为什么、为何、值得、概览”之一；FDE 与唐文斌文章均以五张卡片开场 | 用本期的具体问题、经历或分歧引入，交代必要背景 |
| 章节切碎，段尾再讲一次道理 | FDE 文稿的交付、实施、数据、上岗、组织各自成节，又多次回到业务结果；唐文斌文稿有“创业的方向感是在行动中逐渐形成的”一类总结尾句 | 先列文章主线和各节新增证据，再合并同题章节；允许案例自然结束，不要求每节拔高 |
| 抽象词掩盖具体动作 | “优衣库项目说明了真实交付的重量”“让开放 API 帮助他们寻找更有价值的应用场景” | 标题说明事件或判断，正文写清谁做什么；例如标题可改为“优衣库项目延期半年，团队重写代码”，后句可写“他们开放 Face++ 的 API，观察客户会把它用在哪些场景”——采用前仍须核对字幕中的意图和时间 |
| 对偶和转折变成固定节奏 | 194/230 篇命中“不是……而是……”（同一标点句内最多间隔 60 字），共 633 处；这是复审线索，不是错误数 | 删除虚构的对立面，保留有信息量的真实对比；取消旧规则仅允许引文使用该句式的绝对禁令 |
| 中文语法要求过硬 | RULE 0.5 要求每句都有主语、谓语、宾语 | 改为上下文中的动作和指代清楚；允许中文省略重复主语、无宾语句 |
| 转述与作者解释混淆 | 旧 RULE 10 要给 paraphrases/glosses 都加“作者概括”；145/230 篇出现该标签，共 238 次 | 忠实转述自然标明观点归属；只有新增的编辑框架、类比或推断才明确标注，并仍需证据 |
| 专名规则妨碍中文阅读 | 一处要求固定中文名，另一处禁止翻译专名；内战文稿频繁混排 Lincoln、South Carolina、Whig Party 等 | 有约定俗成中文名就使用，必要时首次附原名；品牌不自造译名，全文保持一致 |
| 单句排查不能发现文章重复 | 现有编辑阶段主要列句式并运行 rg | 增加主线与章节复审、段首段尾连读、全文中文阅读三步，复核归属和限定条件 |

## 针对抽读文章的结构建议

- FDE：可从催发货的 260 多步切入，接着解释数据与流程准备、上岗和复盘、团队分工，再讨论收费与中国企业的条件。把反复说明“业务结果”的段落合并，保留不同案例各自的证据。
- 唐文斌：保留从竞赛、旷视到具身智能的时间线，把 Face++ 客户与数据积累连在一起，把物流场景选择与优衣库交付连在一起，再讨论新公司的模型路线与商业目标。
- 美国内战：先区分战争起因和士兵参战动机，再展开战争过程、解放政策与战后记忆；不把历史题材硬写成科技商业文章。实际重排需再次核对原文，避免倒置事件顺序。

## 验证与边界

- 生成入口 `scripts/run-plan.ts` 已读取两份 prompt；不需要新增加载逻辑。
- `scripts/lib/artifact-validator.ts` 检查文章文件大小、语义容器和样式归属，没有固定章节或金句数量检查，因此取消配额不改变产物契约。
- 保留原有事实、引文证据和 HTML 格式要求；幻灯片的页数与版式规则仍在各自章节中。
- 本轮做 prompt 一致性检查和 `git diff --check`，没有调用模型重新生成文章，也没有以关键词命中率宣称文风改善。效果需由后续新生成的文章验证。
- 此前会话提到的 humanizer-zh 未在当前环境的技能目录中找到；本轮依据仓库规则和成稿完成审查，未声称运行该技能。
