# 冗余资源清理与单集打包实验

日期：2026-09-10。

本轮清理让当前 276 集的发布产物减少了 2,031 个文件，体积减少约 111 MiB。单集实验中，将逐页内容模块合并后，文件数从 93 降到 50，远距离跳页等待减少；首屏提前下载的内容增加，首屏就绪时间只有小幅变化。清理已接入普通构建，模块合并仅用于实验，尚未全站启用。

## 发布产物清理

| 指标 | 本轮清理前 | 清理后 |
|---|---:|---:|
| 文件数 | 23,065 | 21,034 |
| 未压缩体积 | 353.3 MiB | 242.4 MiB |

清理位于 `scripts/lib/shared-assets.ts` 的 `pruneUnusedBoilerplate`，由 `scripts/build-all.ts` 在每集文章和幻灯片组装完成后调用。

候选范围仅包含 `episodes/_templates/public/` 中的模板图，以及 `slidev-theme-academic/public/` 的 `presentation.jpg` 和 `box.svg`。候选必须与原始文件逐字节一致，且编译后的 HTML、JS、CSS、JSON、SVG 中未出现其文件名。模板图还检查不带扩展名的名称，保留可能拼接扩展名的引用。有引用、被修改过的文件，以及不属于候选范围的资源都保留。

此规则清理发布副本，保留单集源码和构建缓存。它不是通用的未使用资源分析器，不尝试推断任意动态 JavaScript 路径。静态扫描得到的候选并未全部删除，最终以字节比较和引用检查共同决定。全量构建复用了 276 集缓存。

本轮实际删除 1,479 个模板图副本，以及 552 个主题示例资源。

当前仍比 Cloudflare Pages 免费版 20,000 文件限制多 1,034 个，尚不能直接免费迁移。

## 实验对象与变量

选择硅谷101 E249《Token经济转点：OpenClaw、Hermes到本地自研的Agent进化之路》，单集 ID 为 `6242033d-a14a-44e3-a622-cbfc7d3c3817`。共 38 页，7 页包含 Excalidraw 图表。

两种构建使用同一份隔离的源码副本、相同的生产 base 和 hash 路由，并执行相同的冗余资源清理。

- 默认组：保留 Slidev 的逐页内容模块。
- 合并组：通过 Vite 配置中的 `manualChunks` 将 `/@slidev/slides/<页码>/md` 归入 `slide-content`，其他模块仍调用 Slidev 原有分组函数。

构建清单确认，默认组有 38 个内容模块，合并组只有 1 个且包含全部 38 页。打包器同时将部分依赖归并进内容包，因此减少的 JS 文件数不止 37 个。两组的 `vue`、`shiki`、`file-saver`、`unplugin-icons` 公共包保持一致。

以下文件数只统计该集独立 Slidev 产物，不含 Astro 站点、文章，也未叠加全站跨集资源共享。

| 指标 | 默认组 | 合并组 | 变化 |
|---|---:|---:|---:|
| 总文件数 | 93 | 50 | −43，约 −46.2% |
| JS 文件数 | 69 | 27 | −42 |
| 内容模块数 | 38 | 1 | −37 |
| 未压缩总字节数 | 997,266 | 988,183 | 约 −0.9% |
| 全部 JS 分别 gzip 后的字节数之和 | 266,715 | 238,516 | 约 −10.6% |

减少文件数并不意味着同比减少体积。页面内容依然存在，主要变化是内容的组织方式，以及合并后压缩效率提高。

## 测量条件

- 本机 macOS / arm64，Chromium 149.0.7827.55，1440 × 1000 视口。
- 主站资源由本地 HTTP 服务提供，文本资源使用 gzip；CDP 模拟 40 ms 延迟、10 Mbps 带宽和 4 倍 CPU 降速。
- 两组先各预热一次，不计入结果；然后交替先后顺序，各测 10 轮，每轮创建新浏览器上下文。
- 图表使用外部 HTTPS 模块。先录制一次完整依赖响应，再向两组回放同一份 HAR，避免外部 CDN 波动。它们的网络延迟不计入本次对比，执行和渲染仍在浏览器中发生。
- HAR 路由会禁用 HTTP 缓存。每轮页面内已加载的模块和 DOM 状态仍然保留，因此下表的预加载后翻页测的是已加载状态，不是第二次打开网站的缓存命中速度。

“首屏内容就绪”指第 1 页实际内容出现在 DOM、字体就绪，再经过两个动画帧；不以 hash 地址变化代替渲染，也不等待固定过渡动画完整结束。FCP 单独记录，它可能只表示页面外壳开始绘制。

进入第 1 页后立即测量 1→2，再测量 2→20。Slidev 52.18.0 会预加载当前页和相邻页，并在 3 秒后预加载全部幻灯片，因此另外等待 4.5 秒，测量 20→19 和 19→20。这几项翻页以目标页内容 DOM、字体及两个动画帧为完成条件；选取的目标页均为文字页面。图表页面另外进行完整渲染和截图验证。

## 测量结果

耗时单位为毫秒，表中为 10 轮中位数，括号内为最小值至最大值。

| 指标 | 默认组 | 合并组 |
|---|---:|---:|
| FCP | 506（500～512） | 518（512～532） |
| 首屏内容就绪 | 598.9（589.8～606.1） | 581.3（573.3～593.9） |
| 立即翻到第 2 页 | 30.1（29.2～31.2） | 27.0（25.9～29.8） |
| 立即跳到第 20 页 | 83.9（81.4～90.3） | 33.1（29.3～36.3） |
| 预加载后，20→19 | 19.9（15.6～26.4） | 18.2（17.2～25.4） |
| 预加载后，19→20 | 20.1（18.1～23.1） | 19.6（17.1～23.4） |
| 首屏时已完成的 JS 资源请求 | 22 | 17 |
| 首屏时已完成的主站子资源压缩字节数 | 224,812 | 243,533 |

子资源字节数不含 HTML 主文档和外部 HTTPS 依赖。合并后这部分首屏传输增加了 18,721 字节，约 18.3 KiB、8.3%。虽然整个 JS 集合压缩后更小，但默认组首屏只需要其中一部分，合并组会提前下载所有页的内容模块。

在这个样本和网络条件下，远距离跳页少等待约 51 ms，差异明显。首屏内容就绪提前约 18 ms，但 FCP 反而晚约 12 ms，不能据此宣称首屏全面加速。相邻翻页及预加载后的差异很小。更慢网络下，提前下载内容的代价可能放大；本次没有测量这种条件，也没有测量真实 GitHub 或 Cloudflare 节点的表现。

## 验证与后续选择

两种产物均逐页打开全部 38 页，没有资源请求或页面运行错误；38 对截图逐字节一致，7 张图表页也经过人工查看。全站清理后，97 项单元测试、首页检查、品牌检查和幻灯片路由检查均通过。

补充静态扫描发现其他 5 集共 28 处图表引用在清理前的缓存中就已缺失，使用的是 `./public/<文件名>.excalidraw` 路径。这些图表不属于本轮删除的模板副本，本次未修改这些原有路径问题。扫描记录位于 `logs/slide-bundling/diagram-reference-scan.json`。因此，本次通过的单集逐页检查不能解释为所有历史节目均无问题。

内容合并值得继续验证：它直接减少每新增一集产生的文件数，且这个样本没有出现渲染变化。但一个样本不足以证明所有布局、公式和交互都兼容。下一步可以选择含公式、不同布局和更长内容的少量节目做同样对照，再决定是否全站采用。当前生产构建仍保留默认拆包。

## 复现与数据

```bash
pnpm exec tsx scripts/experiment-slide-bundling.ts

# 使用已有的两组产物和外部响应记录，再次测量
pnpm exec tsx scripts/experiment-slide-bundling.ts --skip-build
```

脚本还支持 `--id=<episodeId>` 和 `--runs=<轮数>`。当前实验固定使用第 20 页作为远距离目标，要求至少 20 页；更换节目时需确认目标页类型，才能与本报告的文字页耗时直接比较。仅支持没有自定义 Vite 配置的单集。

实验产物、构建清单、HAR 和截图位于 `logs/slide-bundling/<id>/`，该目录不提交 Git。原始汇总及 20 次采样保存在 [实验数据](slide-bundling-2026-09-10.json)，其中记录了浏览器版本、源码 SHA-256 和测量条件。
