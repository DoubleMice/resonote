# 共享播放器后的优化记录

日期：2026-09-10。本轮改动尚未提交或部署。此前的共享播放器已随 `3bd40a4` 发布到 GitHub Pages。

本轮修复图示资源、补齐生成校验，并让首页按需加载后续目录。SVG 预渲染完成单集实验，暂未接入生产构建。最终发布目录有 2,734 个文件、约 61.6 MiB；相比上一轮增加 5 个文件，来自目录片段及前端脚本拆分。此次首页优化主要减少初次传输和 DOM 数量。

## 图示修复与校验

11 个 Excalidraw 文件的文字包含未转义双引号，导致 JSON 解析失败。修复保留文字和其他字段，只补必要转义。复查还发现 18 个文件中的 35 条箭头缺少 `points`；根据各箭头原有的 `width`、`height` 补入直线端点 `[[0,0],[width,height]]`。两类问题有一个文件重叠，共修改 11 集中的 28 个图示文件。

28 个场景均使用现有 Excalidraw 0.18.0 的 `exportToSvg` 独立渲染通过。这个检查验证图示数据能被渲染，不代表对应节目所有页面的布局都已通过检查。

普通产物校验现在检查引用文件是否存在、JSON 能否解析、`elements` 是否为对象数组、可选 `appState`/`files` 的类型，以及箭头和线段是否包含至少两个有限坐标点。生成时的严格校验还会拒绝只包含 `layout:` 配置的独立页面。

## 首页按需加载目录

首页初次输出前 36 条节目。首次搜索、筛选或点击“显示更多”时，加载剩余 284 条。目录片段继续使用 `EpisodeRow.astro` 生成，首页搜索和筛选共享同一个加载请求，没有增加另一套浏览器端模板。

片段地址包含由目录数据和行组件源码计算的版本标识。加载失败时保留首批内容，并允许重试；遇到已经失效的旧版本地址，可以刷新首页取得最新版本。追加条目后同步本地已读状态。带筛选参数的链接会先加载全部条目再筛选；关闭 JavaScript 时，独立内容库仍显示全部节目，首页提供入口。

以下对比使用同一份 320 条目录数据：一组输出完整目录 HTML，另一组按需加载。各测 8 轮，交替执行；本地 gzip HTTP、40 ms 延迟、10 Mbps 带宽、4 倍 CPU 限速。两组都阻止外部缩略图请求，因此这些结果不包含封面 CDN 的网络表现。就绪时间以目录计数初始化、字体就绪及随后两帧为准。

| 指标，中位数 | 完整目录 HTML | 按需加载 |
| --- | ---: | ---: |
| HTML 原始体积 | 951,618 B | 157,895 B |
| HTML gzip 传输体积 | 104,687 B | 23,301 B |
| 初始目录条目 | 320 | 36 |
| 初始 DOM 元素 | 8,289 | 1,439 |
| 就绪时间 | 494.6 ms | 456.9 ms |
| DOMContentLoaded | 437.8 ms | 396.8 ms |
| FCP | 244 ms | 248 ms |

HTML 原始体积减少 83.4%，gzip 体积减少 77.7%，DOM 元素减少 82.6%；本次就绪时间缩短约 7.6%。FCP 没有改善。用户使用搜索或筛选时仍需下载余下目录，因此总阅读会话的流量不会按同样比例下降。

## 单集 SVG 预渲染实验

实验对象仍为硅谷101 E249，共 38 页、7 张图。两组都采用共享播放器和单集内容包。原始组在浏览器中下载 Excalidraw 库和 JSON，再生成 SVG；实验组在构建前导出含字体数据的 SVG，页面以图片加载。

实验脚本只修改 `logs/diagram-svg/<id>/` 中的副本。7 张 SVG 共 214,755 B，分别 gzip 后合计 87,361 B；对应 JSON 共 95,995 B，分别 gzip 后约 9,467 B。两组实验目录均有 29 个文件，预渲染本身没有减少文件数量。

最终测速在没有并行构建或测试的情况下完成，每组计划 6 轮，顺序交替。页面共用的 Google 字体从同一份 HAR 回放，排除其网络波动；Excalidraw CDN 使用真实 HTTPS 请求。条件为本地 gzip HTTP、40 ms 延迟、10 Mbps 带宽和 4 倍 CPU 限速，每轮使用新浏览器上下文。HAR 路由关闭 HTTP 缓存，CDN 和操作系统缓存可能已预热。

| 指标，成功轮次中位数 | 浏览器渲染 | 预生成 SVG |
| --- | ---: | ---: |
| 首屏就绪 | 529.5 ms | 611.4 ms |
| 从首页跳到首张图，直至图示显示 | 10,031.5 ms | 98.1 ms |
| 此时已完成的同源子资源 gzip 体积 | 263,602 B | 353,992 B |
| 此时已发起的外部请求数 | 16 | 2 |
| 成功轮次 | 5 / 6 | 6 / 6 |

原始组有一轮在 30 秒内没有显示图示，失败记录保存在原始数据中，未计入耗时中位数。此前探索测量也出现过外部加载超时；这些样本不足以推算线上成功率。10 秒级等待反映本次机器到外部 CDN 的网络条件，不应解释为所有用户都需要等待这么久。

预生成 SVG 降低了图示加载对外部 CDN 的依赖，但首屏就绪慢了约 82 ms，同源子资源增加约 88 KiB。Slidev 会提前加载图片，SVG 内嵌的字体和绘图路径也比原始 JSON 大，因此提前下载的成本有所增加。

两组逐页检查中，31 页截图逐字节一致，7 张图示页均有像素差异。人工抽看首张图时，文字和图形均保留，差异主要出现在绘制边缘；尚未据此确认所有图示、字体和缩放条件都一致。实验组阻止 `esm.sh` 请求后，7 张图仍能显示。

本轮不推广 SVG。继续推进时，应先控制图片预加载范围，进一步检查截图差异，再覆盖其他字体、背景和画布比例。

## 构建收尾与已知问题

全站共享 Vite 构建已经生成公共资源，原先在各集产物间查重并改写 URL 的后处理不再找到可共享资源。本轮移除了这段逻辑及其旧测试，保留模板资源清理和只读文件统计。检查确认播放器、各集内容和资源未因移除该步骤而变化；首页目录版本地址和 RSS 生成时间不属于该对比。

另外发现 33 集共有 142 个只包含 `layout:` 的页面。原因是在 `---` 与配置之间插入空行，Slidev 将配置当作普通页面，下一页采用默认布局，命名插槽中的图示可能没有显示。这是原稿问题，与共享播放器拆包无关。修复这些分页会改变后续页码；本轮保留原稿和已有页码，并将清单写入数据文件。新增严格校验用于阻止新生成内容继续出现同类问题。

本轮没有修改 Cloudflare、DNS 或线上缓存规则。
