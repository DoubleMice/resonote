内容入口按模型选择 CLI：GPT/Codex 使用 Responses API，其他模型保留 Claude Code Messages 入口。工作流固定 Codex CLI 为 `0.153.4`，沿用仓库现有模型、网关和密钥配置，规范化 `/v1` 路径。只有 CLI 正常完成、文件齐全、产物校验和布局检查通过，才标记为 `generated`。

已用生产同款模型 `gpt-5.6-luna`、`max` 推理强度和现有网关完成实际兼容性调用，收到 `RESONOTE_OK`。完整单集生成仍在验证中，兼容性调用本身不代表内容生成通过。

音频改为流式下载，失败时清理半成品，针对网络错误和临时 HTTP 错误最多重试三次。分块固定使用 32 kbps 单声道 MP3，去除源文件元数据和封面，按字节预算限制时长并检查最终块大小。转写时逐块编码，避免同时保留整集的 base64 数据。

## 性能变化

| 项目 | 修改前 | 修改后 |
|---|---|---|
| 首页 HTML | 1,005,860 字节 | 817,750 字节，减少约 19% |
| 内容库筛选处理 | 每次约 4–7 ms | 每次约 0.2–0.7 ms |
| 连续 6 次筛选的列表节点增删 | 3,180 次 | 0 次 |
| 两集重建加整站组装 | 串行 13.64 秒 | 并发 2，11.62 秒，缩短约 15% |
| 11 个 RSS 源之间的固定等待 | 合计 50 秒 | 去除固定等待，最多并发 3 个请求 |
| Actions 单集缓存 | 每次任务写入新键 | 按单集内容指纹汇总缓存键 |

页面与构建数字来自同一台本地机器。浏览器测量屏蔽了外部封面请求；构建对比选择 `6-mEiwe2NhE` 和 `6a97f287f03e74ee6b03ea5b` 两集，各执行一次，其余 234 集使用缓存。这些数字不是 GitHub 托管 runner 的优化后耗时。

Actions 的历史日志显示，全量冷构建耗时 1,050 秒，缓存全部命中时为 7 秒。因此 workflow 优先保留已有缓存：缓存键使用与单集构建相同的输入指纹，在内容生成后计算，避免每次任务重复保存约 170 MB 的相同缓存。

首页搜索从已渲染的内容库按需读取索引，去除了重复嵌入的 JSON。内容库筛选保留节点，仅在排序选项变化时重排；搜索、筛选和阅读状态脚本由 Astro 打包为可缓存模块。站点仍采用静态页面，无需新增服务或前端框架。

构建和 RSS 共用一个有限并发函数；构建失败时先等待已启动任务完成，再报告错误，避免留下仍在写文件的子进程。文章主题在构建时读取一次。RSS 请求增加 30 秒超时，失败来源保留已有缓存。

Actions 跳过依赖安装阶段的浏览器自动下载；需要浏览器的任务单独缓存并安装 Chromium headless shell。发现任务和转写接口测试不下载浏览器。runner 已有 ffmpeg 时跳过重复安装。
